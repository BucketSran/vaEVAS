# 按规范重构 EVAS 验证与能力登记

本计划面向负责修改 main 的开发者，规定实施顺序、文件范围和验收结果。
2026-10-26 已核对远端 main 为 `f210ebd59dfd5db78eea7ac0751479bc9e02beed`。
本计划已获六批实施与逐批交付授权，PR1 正在实施；尚无本轮合入结果。
开始每批前须重新固定实际基线并检查其他作者的增量。
设计依据为 [ADR-007 至 ADR-009](DECISIONS.md#adr-007)，本版补充独立审查 DR-01 至 DR-06 的处理方案。
记录处理方案不等于审查项已经通过实现验收或复审。

## 交付边界

改造的目标是让规范要求、测试可信度、EVAS 支持范围、四端实测和合入判定各有明确来源。
本轮交付完整条款及资产登记、可检验的资格与 CI 规则、代表案例贯通和按职责迁移。
全部测试逐项取得资格、修复全部已知实现缺陷、实现全部 2023 扩展是后续能力开发，不作为本轮完成条件。

采用 LRM 2.4 基础及明确选入的 2023 变化：7780 的 `expm1`、`ln1p`，
7920 的模拟上下文 `$rtoi`、`$itor`。按完整相关条款核对定义、别名、适用上下文及边界，
未选入的变化继续按 2.4。EVAS 电压域定位不变，Spectre 继续列为待跑。
规范选入不表示任何后端已经实现或通过验收。

现有主线的 3257 方法历史审计和本地 3262 方法候选各保留原身份。
本地 21 文件测试修复另作候选，不能随文档或目录迁移直接并入 main。
已通过方法也须登记审核状态；未发现具体问题、执行通过与判据合格是三种不同结论。

## 目标目录及单一维护源

下列路径规定本轮的目标职责，新增登记正在 PR1 实施。既有入口迁移前须核对消费者，不能一次删除重建。

| 位置 | 改造内容 |
| --- | --- |
| `evas/capabilities/data/`，新增 | 规范身份与选入清单、条款目录、要求、能力、资产、关联及审核记录；作为一个逻辑登记的分文件维护源 |
| `evas/capabilities/registry.py`，新增 | 加载与校验登记，解析版本关联、依赖和资格；不把几个通过结果自动判成整项能力合格 |
| 现有 `catalog.py` | 过渡期改为读取登记的兼容接口，最终去掉手写成绩和第二份事实源 |
| 现有 `registry.json`、`generated/`、节点 README | 保留为只读派生视图，由 `render.py` 生成；历史成绩带执行与判据身份，不转授给当前 main |
| `evas/validation/` | 维护当前案例、刺激、独立参考、检查器、校准、EVAS 专用适配及常用验证入口；承接已有专题模块 |
| `evas/tests/` 与 Rust 测试 | 保留开发回归和内部状态、预算、回退检查；引用共享定义及带身份的生成夹具 |
| `evas/examples/` | 保留教学与接口示例，登记其用途；能运行不授予语义验证资格 |
| `scripts/` 与 `.github/` | 维护仓库级收集、报告、CI 选择和门槛；EVAS 案例、数学判据不继续散落到维护脚本中 |
| `experiments/` | 保留研究批次配置、分析、执行索引与冻结历史；当前维护代码按职责迁移，冻结副本不回写 |
| `benchmark/` | 继续自包含，通过带版本的导出复用资产，禁止运行时导入 EVAS 开发目录 |

模型、数学参考和检查器不反向依赖生产求解器或后端执行器。
EVAS 适配器负责同源模型的准备、输入转换、结果读取和判定对接。
通用电路执行调度仍归独立 circuit harness，不在 EVAS 内另造远端调度系统。
现有通用读取器先查消费者再决定归属，保留一个维护实现，不能因搬目录复制第二套。
过渡期旧成绩作为只读历史导入，新增或修正的当前登记只写入 `data/`。
兼容接口负责读取与转换，不能让旧表、Python 常量和新登记同时维护当前成绩。

## 登记必须表达的关系

稳定 ID 标识对象，版本或内容哈希标识被审核的具体内容。关联须绑定具体版本，不能只指向“最新”。

| 对象 | 必需信息 |
| --- | --- |
| 规范文档与语言配置 | 官方来源、版本、文件哈希、基础版本、选入的具体变化、依赖、冲突或解释缺口 |
| 条款目录 | 正文条款、表项、语法产生式、相关附录与规范性引用；Verilog-A 适用性及排除理由 |
| 验证要求 | 生效规范或独立精度/内部合同来源、适用域、允许行为、观察量、误差/时间预算、必测条件、缺口 |
| 能力 | 关联要求及范围；依赖能力和组合要求分别登记，不由单项结果推定组合支持 |
| 方法与资产 | 当前路径、类型、来源、版本、关联要求或内部合同；文件级 GUARDS 只保留导航意义 |
| 案例与判据 | 模型、参数、刺激、初态、观察、独立答案推导、适用域、正负控、审核记录 |
| 执行、分析与审核 | 三类独立身份，绑定后端/工具链、实际配置、原始数据、判据版本、来源可获得性和范围结论 |

规范选入、EVAS 目标范围、测试资格、运行结果、后端验收使用独立字段。
运行结果包括通过、失败、错误、跳过、预期失败、意外通过和未执行；中断与未收齐的运行另标完整性。
同一方法允许多个问题归因，分别记录实现缺陷、测试问题、未支持能力和证据不足。
不得把这些标签混成互斥的“错误总数”，也不能把配置数、方法数和独立缺陷数混作同一分母。

## 六批改造与 PR 边界

建议六个按结果组织的 PR，按下面的依赖合入。这里规定已授权的逐批交付范围，按各批验收与独立审查后发布并集成。
每批都须独立审查、保留完整原始结果，并给出与实际基线的比较证据。
PR2 的自动门槛进入 main 前，沿用明确记录的人工比较与独立审查，不伪装成门槛已自动生效。

### PR1：规范目录与版本化登记可以核对

修改 `evas/capabilities/catalog.py`、`render.py`、`test_registry.py`、能力目录 README，
新增上面的 `data/` 和 `registry.py`。同步 ADR、术语及必要的规范/外部比较政策入口；
`PROTOCOL.md` 的现行适用规范须和语言配置关联，历史协议及旧收据保留其版本。

1. 固定 2.4 与 2023 官方文件身份，登记规范性引用。用 2.4 的模拟子集附录 C
   核对纳入范围，而非只从现有测试或 G.7 变更表推导全集。
2. 建立独立于要求登记的规范索引，覆盖目录、正文、表格、语法和相关附录；
   每项给出纳入、排除或待判定及依据。正文抽取与索引对账，人工复核自动抽取边界。
   “目录完整”仅表示这些来源项均有处置，不代表每条语义已取得验收答案。
3. 2023 的选入落实到具体变化与必要依赖。例如 7780 和未选入的 7900 都涉及 Table 4-14，
   不能为加入两个函数而整表覆盖 2.4。依赖需要额外规范选择时保留争议项，不由实现偷偷补选。
4. 明确资格变更规则。checker、预算、解释、模型或后端身份变化须按
   [既有重验规则](../../../.agents/skills/evas-validate/SKILL.md#revalidation-triggers)
   重新校准、重分析或执行。撤销或过期沿依赖关系传播；旧结论继续描述旧身份。
5. 用已有通过案例、负控、未支持项和内部合同各贯通一个登记样例。
   其余条目可待补证，禁止为凑齐表格填写推定通过。

验收：删除规范索引中的一个映射会暴露目录缺口；未选入变化不能改变对应预期；
缺来源或缺校准的对象不能取得资格；共享 checker 变更或撤销后，两个消费者均不能沿用原资格。
相同数据重复生成视图结果一致。主要处理 DR-03、DR-05。

### PR2：真实结果与可信基线门槛贯通 CI

修改 `scripts/run_regression.py`、`scripts/ci_evidence.py`、`scripts/ci_selection.py`、
`scripts/evas_check_policy.py`、`.github/workflows/numerical-assurance.yml`。
新增仓库级 `scripts/regression_gate.py` 和 EVAS 验证目录下的版本化已知非通过基线。
扩展 `scripts/tests/test_regression_runner.py`、`test_ci_selection.py`、`test_independent_ci.py`，
为门槛新增行为测试。旧报告只读兼容，不能把缺少细粒度结果的旧证据升级成新资格。

报告链分别保存四项结果：执行是否完整、实际测试结果、与获审查基线的差异、是否允许合入。
`successful` 继续表示原始测试成功，不改成“允许合入”。收集与合并步骤能够保留完整失败报告，
同时拒绝缺失分片、重复身份、导入/收集失败、中断和未知结构。

方法 ID 下保存可识别的子条件、断言/阶段与原因信息，并记录 setup/teardown 失败。
采集成功的子条件，才能比较其是否退化。普通方法早停后没有观测到的条件仍为未验证，不能推定通过。
失败匹配使用稳定条件及语义原因，保留原诊断；不能只凭错误文本哈希认定根因相同。

基线读取合入前已审查的可信提交，绑定测试、判据、语言配置和运行配置。
PR 自己修改基线不能自行消除回退；基线变更须单独列出原因、旧新证据和审查结论。
历史非通过可以保留“已观测、语义待审”身份，但不能据此授予正确性结论。
受本次变更影响且判据发生变化的旧失败，必须重新归因；缺少可比较证据时保持未解决。

首版保留“仅全通过报告可缓存复用”的保守策略。含已知失败的完整报告可上传、比较和判定合入，
但不写入成功缓存。缓存键包含报告格式与实际输入身份；合入结论每次按当前可信基线计算。
工作流通过明确的采集步骤保留原退出码和完整报告，再由必需门槛判定；不能用无条件忽略错误替代。

验收至少包括：

- 旧失败条件 A 换成新失败条件 B，即使方法仍为 failed，也识别为需处理的新差异。
- 既有完整失败报告保持原成绩，匹配可信基线时可以取得独立的允许合入结论。
- 新失败、缺分片、零测试假通过、收集异常和新增跳过/预期失败均不能被默默放行。
- 测试纠错在旧实现重现旧缺陷，并在候选上按同一判据比较；不靠修改基线隐藏新退化。
- PR 内自行增加失败豁免不能让门槛通过；成功缓存不能复用到不匹配的新输入或格式。

这一批必须先于需要新门槛放行的测试修正批次。主要处理 DR-01、DR-02。

支持条目更新必须同时具备具体要求、匹配证据和审核记录；程序检查关联，人工负责充分性判断。
日常流程统一为条款/内部合同、要求、案例与独立答案、校准、修复、回归、独立审查、登记与生成视图。

验收：一处登记变更驱动所有当前视图；撤销资格同步反映到所有消费者；
旧成绩仍能按原身份找到，新分母可重算。对规范变更、checker变更、测试纠错、实现修复、纯迁移
各演练一条交付路径，检查必要门槛不会遗漏，也不会要求无关全矩阵。

## 合入、失败处理与总体验收

依赖顺序为 PR1 → PR2 → PR3 → PR4 → PR5 → PR6。
资产盘点可以在前两批期间只读进行，但其消费者和接口按固定登记版本集成。
PR5 可按模型/判据、读取器/适配、命令入口拆成更小子批，每批独立满足迁移验收。
不因拆分而推迟必要的 CI 接线或历史证据验证。

每批从届时已审查 main 固定输入，保留上批兼容入口，明确报告本批的语义变化和纯迁移。
必要检查失败或审查未解决则停在该批，不把问题混入下一批。
发生问题时回退该批提交或切回旧入口，保留新旧证据与原始失败；不得删测试、放宽阈值或改写旧成绩来恢复绿色。

最终完成标准如下：

- 规范核对全集、2023 具体选入和依赖有记录，EVAS 目标子集可枚举。
- 当前资产和实际收集方法全部登记，待映射与待补证对象明确可见，历史分母不混算。
- 原始结果、基线比较、合入判定相互独立，已知失败的条件替换负控能检出新差异。
- 判据资格有适用范围和版本依赖，变更/撤销不会继续显示当前支持。
- 每批迁移均验证真实 CI 收集与消费者，代表历史收据可以读取、校验和解释。
- 四端表由一个登记维护源生成，所有支持结论可追溯；Spectre 待跑保持可见。
- DR-01 至 DR-06 的处理取得对应证据并经过独立复审；仅修改本计划不能关闭这些项目。

本页规定验收，实施与交付状态由固定任务入口维护。未完成的验收不因代码或计划已写出而关闭。

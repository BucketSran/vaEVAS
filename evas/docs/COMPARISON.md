# 四后端支持范围与精度评测

本表说明四个后端在共同精度要求下能完成哪些电压域任务，也是论文取表入口。
**本轮扩展为 20 组基础特性和 24 组工程组合，共 71 个必测变体。**
每个变体按三个精度档分别测试四个后端，共 852 个固定评测位置。
四后端均已实际执行。EVAS 完整通过 105/213 个“变体×档位”，另有 81 个证据不足、27 个拒绝或超时。
这些数量用于定位工作，不是语言覆盖率或后端排名；各组结论见下表。

通过只覆盖具名条件、观察点和误差预算，不代表完整语言支持或全时域误差证明。
这批用例来自开发需求，尚不是独立留出的论文评价集。旧判据和旧成绩保留在[历史结果](#historical-results)中。

阅读顺序：[精度控制](#accuracy-controls) → [表格构建与标记](#table-design) →
[验收误差](#acceptance-budgets) → [实际配置](#measured-settings) → [测评结果](#支持矩阵)。
详细推导、边界规则和失败归因见[配套评测标准](COMPARISON-METHODOLOGY.md)。

## 1. 四个后端如何控制精度

| 后端 | 控制方式 | 怎样理解 |
| --- | --- | --- |
| Spectre | 求解容差、积分方法与误差控制、最大步长 | 决定每一步如何求解、何时缩步；精度预设可能覆盖请求值 |
| ngspice + OpenVAF-R | ngspice 的容差、瞬态积分与步长控制 | OpenVAF-R 编译模型，ngspice 负责数值求解 |
| Gnucap + modelgen-verilog | Gnucap 的容差、积分与步长控制，时间分辨率 `dtmin` | modelgen-verilog 编译模型，Gnucap 负责数值求解 |
| EVAS | `vabstol`、`reltol`、`max_step`，以及受支持路径的误差传播检查 | 作用取决于求解路径；解析传播也存在有限精度误差，收紧设置可能改变是否接受结果 |

模型中的 `timer` 时间容差和 `cross` 时间、表达式容差另行约束事件定位。
`strobe` 规定求解或观察时刻，本身不保证电压误差达标。
**内部设置是控制手段，外部测试误差才是验收标准。** 相同参数值不表示同等输出精度。

<a id="table-design"></a>

## 2. 表格怎样构建，标记是什么意思

基础特性检查一种语言写法或算子；工程组合检查采样保持、边沿、滤波等共同工作时的行为。
每行先固定必测条件，覆盖该行适用的初态、信号幅度、事件前后、持续运行或多实例情形。
具体范围写在行名和[条件说明](COMPARISON-METHODOLOGY.md#test-conditions)中，不把一次成功推广到所有写法。

单个用例通过记为 **✓**；确认失败直接写原因，如“编译失败”“漏事件”“输出超差”。
尚不能下结论时，写清缺少什么，例如“边界未验收”；尚未细分的保留“待验证”。
没有运行的写“未测”。这些待完成项不等于失败。

旧表中的 p/N 是已通过数与计划用例数，未测和失败仍各自保留。配置尝试次数不计入用例数。

本轮每组分别列 Q1、Q2、Q3；同组有多个必测变体时，只有全部通过才打勾。
更严一档的某次成功，不自动替代另一档预先选定配置的实际失败。
“数值达标；取证待补”表示波形误差已达标，但尚不能给整项通过；它不等于后端不支持。

<a id="acceptance-budgets"></a>

## 3. 如何统一验收标准

**同一个测试用例，四个后端使用相同的模型、输入、行为要求和允许误差。**
各后端可以采用不同的容差、步长和积分方法，但都要达到同一验收要求。
验收同时检查电压误差、事件时间、次数与顺序，关键边界也要检查。

不同类型的用例可以有不同误差预算，但必须在测试前确定，不能根据运行结果放宽。
本轮固定参考刻度 A=1 V，Q1、Q2、Q3 的总电压误差上限分别是 **10.1 µV、1.01 µV、101 nV**。
计数、顺序和分支另有行为要求，不能用电压误差抵消。
预算依据和边界判定见[评测标准](COMPARISON-METHODOLOGY.md#numerical-acceptance)。
尚未按共同标准完成验收的历史结果在下文单独列出，不与新测试合并计算通过率。
未通过时，先查实际设置和观察，再做精度扫描与反例定位。
“工作点失败”“输出超差”描述结果，是否属于配置问题或后端缺陷另按[失败归因流程](COMPARISON-METHODOLOGY.md#failure-attribution)判断。

## 4. 测试实际采用了哪些配置

EVAS 本轮执行源码为 **`519d5e28`**，包版本仍为 **0.14.0 / IR18**；提交和内核哈希标识具体实现。
213 个 EVAS 位置全部使用同一个服务器 release 内核；内核、编译器、源码清单和其余后端身份见[执行记录](../../experiments/backends/support/README.md#precision-breadth)。
Spectre 为 21.1.0.509.isr12，ngspice 为 46，Gnucap 自报 snapshot 2026.07.29。
OpenVAF-R 和 modelgen 未取得可靠版本号，保留二进制或镜像哈希，不把软件包名称当作版本读回。
选择“用例＋后端＋Q 档”就在运行前固定配置。下列配置是候选，只有实际验收通过后才取得该用例的配置资格。

| 后端 | Q1 / Q2 / Q3 配置 | 相对容差值 | 电压绝对容差值 | 方法与步长 |
| --- | --- | --- | --- | --- |
| Spectre | base / both / deep_bound | 10⁻⁶ / 10⁻⁹ / 10⁻¹¹ | 1 nV / 1 pV / 10 fV | `traponly`；请求 T/32、T/256、0.0004T |
| ngspice + OpenVAF-R | base / both / deep | 10⁻⁵ / 10⁻⁸ / 10⁻¹⁰ | 1 nV / 1 pV / 10 fV | `trap`；请求 T/32、T/256、T/2048 |
| Gnucap + modelgen-verilog | base / both / deep | 10⁻⁵ / 10⁻⁸ / 10⁻¹⁰ | 1 nV / 1 pV / 10 fV | `trap` 设置；请求 T/32、T/256、T/2048，受时间刻度量化 |
| EVAS | base / both / deep | 10⁻⁵ / 10⁻⁸ / 10⁻¹⁰ | 1 nV / 1 pV / 10 fV | 按模型选择求解路径；请求 T/32、T/256、T/2048 |

表中容差是有有效回执时的值；编译或运行失败、缺少读回的配置不能沿用其他运行的回执。
Spectre 的 `conservative` 预设将请求相对容差再缩小 10 倍，所以它与另外三者的实际值不同。
T 是用例时间单位：42 个变体为 1 µs，另外 29 个为 2⁻²⁰ s。
例如 T=1 µs 时，三档 EVAS 最大步长为 31.25 ns、3.90625 ns、0.48828125 ns，Spectre Q3 为 0.4 ns。
二进制时间单位下不能套用这些十进制值。

ngspice 固定 `trtol=7`、`chgtol=1e-14`、`itl4=10`；Gnucap 固定 `trtol=7`、`dtmin=1e-16`、`dtratio=1e9`。
三档电流绝对容差请求分别为 10⁻¹³、10⁻¹⁵、10⁻¹⁷ A；它不是本表电压误差预算。
Gnucap 的 `trap` 回显不保证每一步都用梯形法，已核对的 IDT 路径在首步缺历史时采用 Euler 启动。
两个开源后端的历史启动、原生导出或实际方法路径还有取证缺口，不能把所有设置列为已取得完整资格。
各后端有效电流容差、固定选项、逐用例步长、读回与参数路径证明见[本轮收据](../../experiments/backends/support/README.md#precision-breadth)。
设置来源和波形来源分别验收；写进网表不等于证明实际生效。

表中“数值达标；取证待补”表示导出的波形已满足数值检查，但还缺少相应的设置或观察依据，不能据此判断该功能不受支持。以下情况尤其需要分清：

- F01、F09 的 ngspice 编译失败发生在所测层次实例中，不能据此说宏或参数都不受支持。
- F03、F04 在分支边界两侧取相邻浮点数。必须先确认实际输入保留了这一区别，才能把输出分支不同归为仿真器错误。
- F07、EC01、EC02 等事件组合还要证明完整回调时间区间位于允许窗口。输出值和计数正确，不能代替回调时刻的证据。
- F14、EC16 要分别确认直流初始化和瞬态导数阶段。折点处不凭空指定唯一导数，左右单侧值仍须检查。
- F20、EC18、EC19 分别检查原始相位电压与连续正弦输出。正弦准确不能消除原始相位在环回边界的取证缺口。
- EC03、EC13 要求停止时刻已观察到最后一次回调。这是卡片额外规定的工程要求；若只差这一项，不能直接认定违反语言标准。
- EC05、EC22、EC23、EC24 共 48 个测试位置用于支持或语义探查。它们保留在固定分母中，尚不能获得完整通过。

单次超差也不直接证明仿真器存在缺陷。例如 Spectre 的 EC12 在 Q2 固定配置下略超预算，而 Q3 更严配置数值达标。表格保留两档各自的结果。

ngspice 的 F03 导出修复后，36 个位置全部取得波形。冻结的配置读取器尚未接受带引号的节点引用，因此保留分析错误，不能给出完整判分。另一个实际发现是：请求 0.5 左侧相邻浮点数时，三档导出的输入均为 0.5；原因仍未知，不能直接归为比较器缺陷。

### EVAS 下一步需要补什么

本轮新增的数组更新、PWL 斜率和局部相位精度修复，解决了已复现的拒绝。
它们没有使全部组合通过。EC21 的 Q3 原来在 89.85 s 完成，本次超过相同的 90 s 限制；这个回退保留为失败，原因尚未确定。应按以下原因分别推进：

| 问题 | 代表组 | 下一步 |
| --- | --- | --- |
| 历史误差包围过宽，或细化不能缩小已有状态误差 | EC03、EC12；其他严格档位见上表 | 先改误差传播与状态分解，再用原请求复验，不能只加大计算预算 |
| 在本轮 90 s 阶段限制内未完成 | EC03、EC07、EC08、EC10、EC21 | 找出重复传播与细化成本，同时保持原精度和历史规则 |
| 尚不支持的组合 | EC20，以及 EC05、EC24 支持探针 | 单独细化近邻事件闭包、边沿历史驱动积分和复位 DAE 的契约与实现 |
| 输入阶段、回调时刻、环回侧或观察证据不足 | F03、F04、F07、F14、F20 及有关组合 | 先补观测和参考依据，再判断是否需要改求解器；不复制 Spectre 的偶然舍入侧 |

[精度控制 issue #119](https://github.com/BucketSran/vaEVAS/issues/119)与
[比较表 issue #96](https://github.com/BucketSran/vaEVAS/issues/96)继续保留这些义务。
[已有 #131](https://github.com/BucketSran/vaEVAS/pull/131)保持不动。
本轮没有性能优越性结论，也不能根据两个开源后端尚未补齐的证据推断其整体精度低于 EVAS。

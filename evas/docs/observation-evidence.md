# 瞬态响应的观察证据

`transient` 的响应可包含 `observation_evidence`，版本为 1。旧内核没有此字段时，Python 仍接受响应，观察证据保持缺失。请求 IR、求解容差、事件日程、状态提交和原有 `solutions`、`transient` 字段不变。静态 `solve` 当前不提供此证据。

这是内核已有认证结果的导出接口。它不授予论文观察资格，不证明连续时间最大误差，也不认证调用者随后生成的报告。

## 字段与索引

| 字段 | 含义 |
| --- | --- |
| `schema_version` | 此可选证据接口的版本，目前为 1，不改变 IR v18 |
| `nodes` | 必须与响应的 `nodes` 完全相同，绑定区间列顺序 |
| `effective_controls.absolute_V`、`relative` | 本次求解路径实际使用的已解析、已验证电压绝对容差和相对容差 |
| `effective_controls.stop_s`、`max_step_s` | 实际 Trajectory 配置中的终止时间和最大步长设置 |
| `effective_controls.max_step_applied` | 此路径是否实际把 max_step 用作事件控制器推进上限。无动态的逐点工作点及当前隐式历史路径为 false；读到该设置不代表它限制了这些路径的积分步骤 |
| `sample_origins` | 与 `solutions` 和 `transient.times` 等长，逐行说明产生记录的路径 |
| `initial_settled` | 仅在首个请求时刻是 t=0 且该路径完成初始化/求解后提供 true；缺失或 null 表示没有此项证据 |
| `voltage_bounds_V` | 与 `solutions` 等长。每行是按 `nodes` 排列的 `[lo,hi]` 数组，或 null，表示此路径没有导出该行区间 |

时间直接使用 `transient.times`，证据中不重复保存。`initial_settled` 只描述已返回的 t=0 首行。事件控制器会在收集该行前处理 t=0 应触发的事件，因此这个字段不保证该行在首次 timer/cross 回调之前。需要这种初态的外部合同仍须检查实际事件顺序。请求不含 t=0 时不提供此字段。

原生来源取值如下。

- `stateless_working_point`：按请求时刻求解工作点，没有接受积分步。`accepted_steps=0` 与此相容。
- `accepted_controller_frame`：从事件控制器已接受的完整帧读取电压和状态。
- `certified_causal_frame`：从提交事务准备的因果阶段帧读取。它可能早于该事务最终提交的存储时刻，保留自己的请求时刻、状态与认证区间。
- `implicit_history_evaluation`：读取已认证隐式历史在请求时刻的包围，并求解原始同时关系。
- `unknown`：协议允许保留未知来源，不可转称已接受步。

这些标签说明该行的生产路径，不把各路径统一称为 accepted integration step。它们也不替代实际版本、源代码与二进制身份的绑定。

## 区间数学与范围

已有仿射/事件证书在原 IR、实际输入、旧状态和算子历史区间上求节点包围。隐式路径已有状态/代数坐标的区间，在观察时通过电压预算及原始同时关系检查。接口仅保留这些检查中已经算出的节点区间；事件根窗口和历史不确定度随原证书传播。

数学解的区间不一定包含返回的近似电压。导出时取该认证区间与返回值的 hull，也就是 `lo=min(certified_lo, value)`、`hi=max(certified_hi, value)`。这样导出区间同时包含认证真值与近似返回值，可能比原证书稍宽。区间运算已使用向外舍入的 binary64 端点；导出不重新舍入或执行收窄运算，min/max 保留原端点。JSON 数字往返须保持这些 binary64 值，另行转成低精度文本时，调用者负责向外舍入及新的导出误差。

对观察行的返回值 v，可以用 `max(v-lo, hi-v)` 作该节点的保守前向误差界。用于科学误差判定时，计算这个差值也需要向外舍入。它不是残差，也不是从请求容差拼成的虚构区间。预算检查通过不保证这个界低于某个独立论文导出预算；宽区间必须完整保存。

区间针对内核使用的 binary64 IR/PWL及其已传播历史。十进制源码到 binary64 的转换、外部源合法性、名义时刻表示、其他文本导出格式和其他后端的 native/strobe 语义仍是独立义务。仅有该字段不能把论文表的 I 改为 P。

无动态仿射工作点和事件控制器、历史/隐式消费者提供已有节点包围。静态非线性工作点路径已有其他认证过程，但本接口尚未透传其逐节点包围，因此返回 null；不以 residual/correction 或电压容差回填。新增求解路径也必须保持缺失，直到拥有可导出的实际区间。

## 验证与消费者

Python 响应验证器检查版本、节点一致、逐行数量、区间有限且有序，以及返回值处于导出 hull 内。它接受合法宽区间和 null，不替调用者评估科学方法或论文阈值。旧响应仍可解析。未知版本、错位列/行、反向或非有限区间、缺少返回值的区间会被拒绝。

实现入口位于 `rust_core/ir/src/lib.rs` 的可选类型、`rust_core/src/observation.rs` 的证书传输、`settlement_bounds.rs`、`analog.rs`、`implicit_dynamics.rs` 的原证书消费者，以及 Python `src/evas/protocol.py`。帧仍由原事务所有者提交；证据随相应 Solution 克隆，不改变状态或历史。

`tests/test_observation_evidence.py` 通过公开编译/瞬态接口覆盖逐点工作点、实际控制值、事件采样后的放大、近零绝对误差、相邻 timer 的不同因果阶段、隐式历史、未透传路径的 null 和旧响应兼容。非法区间和过宽但合法的区间分别校准格式拒绝与资格边界。生命周期及事件/历史回归仍由相应测试模块负责；这些测试不执行 Spectre，也不建立跨后端对齐。

证据随观察行数增长。大量节点及密集观察会增大响应、内存和保存文件；调用者须在原文件/目录预算下实测，使用保持 binary64 数值的紧凑 JSON。不得通过删行、丢未知证据或降低精度绕过观察与容量要求。

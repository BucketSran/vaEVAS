# EVAS 技术手册

本手册解释 EVAS 如何求解电压关系、推进事件、保存历史和控制误差。
使用与构建先读 [EVAS README](../README.md)。审查功能改动时，从
[功能对应表](../README.md#review-map)找到数学章节、源码、独立契约和回归。
判断模型是否在支持范围内，先查[能力表](CAPABILITIES.md)，再读对应章节。

## 为什么保留这六份文件

本目录有一份阅读入口、一份能力表和四个技术章节。它们分别维护不同信息：

| 文件 | 维护的内容 | 其他内容放在哪里 |
| --- | --- | --- |
| 本页 | 阅读顺序与章节责任 | 构建、API 和源码对应表在 EVAS README |
| `CAPABILITIES.md` | 支持范围、缺口和证据状态 | 数学推导在四个技术章节 |
| `NUMERICS.md` | 电压方程、线性代数、Newton 和工作点验收 | 历史推进在 CONTINUOUS；事件验收在 EVENTS |
| `EVENTS.md` | 事件定位、条件、顺序赋值和同刻联立关系 | 算子自身的历史在 OPERATORS；联合重启在 CONTINUOUS |
| `OPERATORS.md` | 直接输入算子及波形的公式、历史和误差 | 积分反馈、导数和滤波的联合网络在 CONTINUOUS |
| `CONTINUOUS.md` | 联合状态方程、DAE、传播、复位闭包和动态 guard | 通用电压求解在 NUMERICS；事件语句规则在 EVENTS |

同一算子可以经过不同求解路径。例如，直接 PWL 输入的 `idt` 使用解析积分；
带电压反馈的 `idt` 进入联合连续网络。因此两个章节各解释自己的路径，
不能把直接输入路径的限制读成整个算子的限制。
执行次数、测试数量和 PR 修复过程保留在实验收据或固定历史链接中，不在正文重复维护。

## 理解实现的主线

源码经过语法解析和实例绑定，生成有版本的 IR；内核把贡献汇总成支路方程，
求出未知电压。瞬态还会维护输入、事件与算子历史，并对候选结果统一验收。
公开 API 在[模块与接口](../README.md#模块与接口)。

阅读每项动态能力时，可以依次检查它的方程与假设、历史归属、试算/提交规则、
误差如何进入输出预算，以及不能支持的组合。一个方程残差很小的解，
仍可能使用了不准确的历史；算子单独正确，也不能证明反馈或事件组合正确。

## 参与讨论与改进

Issue 可以围绕能力 ID 提出，附上版本、最小模型与刺激、数学/规范依据、
期望结果和实际结果。不需要先修改内核：数学反例、规范解释、检查器问题和性能回退
都可以独立讨论。协作与文档语言约定见 [CONTRIBUTING](../../CONTRIBUTING.md)。

能力表维护实现和证据状态，手册解释方法，validation 保存独立契约，
experiments 保存实际执行。历史记录继续绑定原版本；合并代码不会替旧实验更新结论。

## Feature documentation contract

新增或修改语义/数值能力时，在对应章节更新以下内容；一个小改动可以只修改相关段落。
无需为每次任务新建设计、计划、KPI 或 review 日志文件。接口/工具类改动只说明适用部分。

1. **行为与组合边界**：能力 ID、合法输入、输出、单位、初值；逐项注明支持/拒绝的阶数、参数、
   输入依赖、嵌套、事件和反馈组合。入口不支持的合法语言写法是能力缺口，不是标准要求拒绝。
2. **依据**：规范版本/章节、论文或固定源码提交；区分规范要求、数学推导、EVAS 选择与后端观测。
   开放网页/主分支链接可作导航，算法或兼容性主张需要固定版本，未固定时注明。
3. **数学与误差参考**：方程/状态转移、历史依赖、假设与边界反例；固定精确参考所指的输入
   （例如 binary64 PWL 的实数解释）、初值、时间与单位。分别报告解/历史误差、残差和观察误差，
   计入累计误差及网络放大；小残差不能替代历史精度，有限样点不能证明连续时间误差界。
4. **数值方法与生命周期**：算法、误差/终止判据、不可判定和失败处理。历史属于实例展开后的
   调用点 ID，不能按赋值目标或仅按源码坐标分槽。每次试算从已接受历史出发；值、误差界、队列、
   状态、电压与事件记录全部验收后原子提交；取消/失败不消费历史。同刻输入改变必须重新试算，
   候选值缓存不能只以时间为键；矩阵等复用也须说明依赖。
5. **实现**：源码入口、数据责任及可检查的规范化 IR；不同等价语法落到共同语义，贡献进入统一
   方程，程序赋值保留顺序。说明必要复杂度/成本；只对实测范围报告性能。
6. **三类独立验证**：链接数学答案与正反校准、适用的语义不变性、同一引擎的失败后完整性证据。
   独立贡献可交换，依赖赋值不可交换；重命名须保持绑定，增加观察点须保持原模型关系。
   回退检查须在实际取消/失败后比较已接受历史并重试，重启进程成功不能替代它。
   固定输入/构建/检查器身份，区分纯数学校准、仿真执行、新执行、复用和重判；缺项明确留作缺口。
7. **限制与贡献入口**：已知差异、未完成证据、相关 Issue/PR。给出能复现问题的最小输入或定位方式。

独立积分答案、不变性回归和生命周期义务见
[DYNAMICS_CONTRACTS](../validation/DYNAMICS_CONTRACTS.md)。
复位观察、时间绑定及生产控制器提交规则见[共同闭包](CONTINUOUS.md#shared-lifecycle-closure)。
先审查冷启动、续算、事件观察和未来历史各自使用的状态，再检查数值方法与验收。
这些开发检查不改变原验证矩阵的分母，也不自动增加能力表中的支持范围。

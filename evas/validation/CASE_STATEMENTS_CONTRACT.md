# 有限标量 case

本开发切片对应 LANG 和 #65。只扩展标量 `case(expr)`、一个或多个以逗号分隔的标签、
最多一个 `default` 和 `endcase`。标签可为当前条件上下文接受的纯标量表达式。
`default` 可以出现在任意位置，冒号可省略。匹配标签按源码顺序选择，执行首个匹配体；
没有匹配时执行默认体，没有默认体则保持进入 case 前的局部值或状态。
所有输入数值必须有限。实数匹配采用精确数值相等，不作整数截断，不引入容差比较。

当前仅接受至少一个非 default 标签，每个 case 最多 16 个标签。生成条件树另外受
既有 96 层容器深度和 100000 项展开预算限制，部分小于 16 个标签的程序也可能达到预算。
这些是实现资源上限。`casex/casez`、四态位匹配与整数隐式转换没有因此开放。

## 降低与执行

Python 的 `syntax.Parser._statements` 将每个标量匹配 `s == label` 降低为先 `s <= label`、
再 `s >= label` 的两层既有 Conditional。两次比较之间没有程序赋值，
未匹配路径指向下一个标签。选择表达式与标签均无副作用，保持程序赋值顺序。
后续内联、数组/循环展开和实例绑定继续经过原路径，Rust IR17 和内核没有新增字段。

普通 analog 体的分支只允许局部 real 赋值，贡献留在 case 之外；选择条件仍要求
输入/inout 的分段仿射表达式。纯函数沿用有限 real 分支及所有未选臂的结构验证。
监测事件体可依据输入电压/参数选择既有状态赋值；事件条件读取状态、间接反馈或
历史算子仍拒绝。`initial_step` 的初始化限制仍由原契约处理。
缺失分支初始化、非法函数臂、未知名字及历史调用不能因未选分支而隐藏。
瞬态条件无法认证时沿用原条件精度拒绝，不把窄区间当作精确匹配。

## 独立答案与限制

[test_case_statements.py](../tests/test_case_statements.py) 通过公开编译/Rust 入口核对
重复标签、多标签、默认位置、相邻 binary64 值、等价 if 改写、嵌套选择、
函数顺序赋值、事件赋值及观察点加密。它同时检查拒绝边界和展开预算。
没有新增回退或状态协议，既有 event_conditions、event_body_loops 与 initial_cross
回归检查事件条件和顺序路径。开发测试不折算为正式资格条件。

[case_statements](cases/case_statements/) 冻结五个 DC 输入 `[0,1,2,-1,0.5]`。
普通 case 的独立输出为 `[3,3,7,9,9]`，纯函数输出为 `[3,4,5,5,5]`。
`.scs` 与独立手写 manifest 采用同一 VA、九个查询时刻和相同精度设置，
本地真实 Rust 输出满足这些答案且相互一致。固定 Spectre 比较预算为 `1e-8 V`，
实际远端对照尚待执行；没有此证据时不声称 Spectre 行为对齐或推荐合并。
这份 DC 用例不能证明动态越过相等边界、任意状态 case、运行时循环或分析生命周期。

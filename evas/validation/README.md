## 与 EVAS 及 VABench 的关系

VABench 的 case 必须对应实际有用途的 Verilog-A 电路建模需求；每个任务需说明
应用场景及为何需要该行为模型。独立验证探针可以是用于区分语义错误的最小人工案例，
不能因覆盖一个语法点就自动成为有工程价值的 VABench 任务。

EVAS 面向明确声明的电压域 Verilog-A 行为及其交互，与 Spectre 对标，支持该范围内
尚未出现在 VABench 中的电路。它同时为无需商业仿真许可证的复现和 agentic eval
提供执行后端。其他开源链路的缺口由固定版本实验确认；EVAS 的支持、精度、成本
和反馈作用分别验证，不以现有家族白名单或总分接近代替语义正确性。

验证集放在 `evas/` 下便于关联仿真器版本和回归，但需求、独立答案与判据不能从
EVAS 当前实现反推。共同契约面向 Spectre、ngspice＋OpenVAF、
Gnucap＋modelgen-verilog 和 EVAS；后端适配只处理调用、网表外壳与输出格式。
模型改写须作为独立编码条件记录，不能替换失败的原始条件。

VABench 的生成、测试平台及修复任务由 [tasks/](../../tasks/README.md) 维护。
既有 400 家族属于应用与回归层，不能代替本目录的独立验证。
跨后端实验配置、分析和整理后的结果归 [experiments/](../../experiments/README.md)，
共用环境归 [containers/](../../containers/README.md)；原始运行输出按仓库约定放在
本地 `runs/`，结果须绑定契约、源码、工具版本和实际生效设置。

## 当前审查顺序

1. V1/V2：静态传递、参考、差分、共模与供电关系。
2. V3/V4：迟滞历史、事件定位、采样、保持与复位。
3. V5/V6：延迟、边沿、周期以及连续动态的精度与观察条件。
4. V7：唯一线性/非线性反馈、实例隔离及显式对照的边界。

每组先审查代表契约，再补尚未覆盖的独立行为义务。八张卡不能证明整组覆盖完成。
起步卡已有编码、独立答案及有限校准，并按 Spectre 在先的顺序完成四后端试点。
下一步落实输入根/导出时标/电压误差界和单独时间指标，继续完善观察资格；新增模型的四后端执行已完成。
已完成的诊断与原始失败随 v1 保留；新条件或新设置不覆盖旧结果。
修订测试已取得固定四后端基线，后续再依据证据安排 EVAS 修复。详细完成条件见设计规格。

## 来源与修订

本设计由项目此前的研究规划整理迁入，保留 DVS-2 修订标识。后续修改以本目录为准，
在 PR 中审查；旧规划及历史运行记录不作为当前设计已验证的证明。
规范与外部建模需求的公开出处见设计规格中的来源表，当前不分发第三方手册。

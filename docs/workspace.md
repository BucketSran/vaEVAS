# 工作区约定

## 已确定的方向

- 项目和新公开仓库名称为 `vaEVAS`。
- 面向 DAC 投稿，以 benchmark 与评测体系为主贡献方向。
- 采用 Harbor 作为 eval harness，任务沿用其原生格式。
- 在同一仓库维护 EVAS 完整源码，支持任务、评分和仿真器同步修改。
- 共用容器环境目录命名为 `containers/`。
- 后续开发与设计在本仓库维护，旧仓库及规划材料作为审查与迁移来源。

## 工作区职责

| 工作区 | 维护内容 |
| --- | --- |
| `tasks/` | 任务规格、公开材料、参考解、任务环境和验收逻辑。 |
| `evas/` | 仿真器完整源码、构建及语义回归验证；`validation/` 维护独立的跨后端验证契约。 |
| `containers/` | 共用镜像构建、依赖和运行环境。 |
| `experiments/` | 实验配置、统计分析、图表生成及整理后的结果。 |
| `scripts/` | 仓库级维护与检查工具。 |
| `docs/` | 设计讨论、已确定方案和使用说明。 |

各区域内部结构按实际需求建立。任务定义、评分规则与执行结果应保持可追溯关系。
`runs/` 用于本地原始输出，已被 Git 忽略。

[独立仿真器验证集](../evas/validation/README.md) 已进入设计阶段，尚无可运行用例或后端结果。
其需求、答案和判据不依赖 EVAS 当前实现，且与 `tasks/` 的 VABench 应用任务分开。
与该验证集直接相关的设计在 `evas/validation/` 维护，避免在 `docs/` 重复保存一套规格。

## 待后续设计

以下内容当前没有定案：

- 题目分类、数量、难度、数据划分和单题交付范围。
- 最终评分方式、测试有效性衡量方法以及独立验证证据。
- EVAS 的具体支持范围、内部架构与源码迁移批次。
- 容器组织、软件打包和发布方式。
- 模型及 Agent 基线、实验预算和正式结果。

讨论中的具体目录示例和实现建议不自动成为必须实现的要求。

## 迁移与统一修复

旧 vaBench 和 EVAS 作为待审查来源保留。迁移应围绕具体需求或问题逐批进行，
记录来源，检查规格与实现，并对迁入部分重新验证。

发现失败时，先区分任务规格、参考解、评分器、仿真器和执行环境的责任。
可以在同一次改动中修复多个工作区，但应说明原因、影响范围和验证结果。
已有成绩不能代替对新版本的验证。

正式实验固定任务、EVAS、镜像以及 Harbor/Agent 配置的组合。
修改评分或仿真语义后，识别受影响的实验，完成必要的重跑再更新比较结论。

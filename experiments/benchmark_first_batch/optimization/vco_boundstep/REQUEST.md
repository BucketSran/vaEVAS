# VCO 动态步长候选实验请求

本目录是原创优化候选，尚未建立 Harbor 正式任务，不计已校准题数。
电路用途是 PLL 瞬态仿真中的连续相位正弦 VCO，频率覆盖 4–400 MHz。
同一模型用于低频启动、缓慢调谐与高频工作。baseline 在全程按最高频率限制时间步，
reference 按当前频率限制时间步。二者使用相同的 points_per_cycle=64、频率映射、
相位积分和输出公式；不能通过降低分辨率或放宽 Spectre 容差取得成绩。

待验证的声明是低频工作区减少实际接受时间步，并在规定解析相位误差内保持完整波形。
v2 两侧三条件功能通过，恒频实际步数符合 bound_step 限制；单轮计时不声明性能改善。若 Spectre 的误差控制本身支配步长，
或实际差距不能复现，则退回候选。动态输入的功能判据必须先通过。

执行文件是 baseline.va 与 reference.va。分别重命名为 dut.va，使用 cases.json 的
三个独立网表，通过 evaluate.py 的 evaluate(rows, case, work) 验证。
低频 case 的固定工作负载为 20 us、7.96 MHz、159.2 周期，其它 case 检查调谐斜率、
控制电压上下钳位、高频端及连续相位。解析判据对输入 PWL 作分段精确积分，
检查所有实际采样点及 4097 个独立均匀探针，最大电压误差 3 mV。恒频两个条件逐相邻时间点独立核验相位前进不超过
1/64+1e-10 周期，不能降低规定波形分辨率。

请由协调者通过现有 harness 排队运行，不新增远程 SSH 编排。
先每侧做一次不计时校准/热身并保存编译日志与完整版本身份。
功能通过后低频 case 至少交替执行 A B A B A B A B A B，固定单线程、同一机器、
同一容差和 netlist。保存每次 Spectre 本机仿真 elapsed/CPU time、接受与拒绝步数、
总 harness 墙钟时间，编译缓存、排队、许可证等待和网络开销分列。
按 benchmark-checklist 保存机器 load average、核心数及并发竞争。
另外做一次不纳入计时的 limiter 定位，优先使用 Spectre 统计与 per-process CPU；
如已有 Spectre profile 功能可记录 AHDL 热点，不用 profiler 数值作最终成绩。
步数和实际已完成周期用独立波形判据校准，保存失败数与结束时间。

性能测量不能把 PSF 保存点数直接称接受步数，必须读取 Spectre 实际统计。
比较两侧中位数、范围和重复步数；只有显著超出波动且功能全过时才将本候选立为正式题。

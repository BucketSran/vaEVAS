# 当前 31 条件的故障归因

2026-09-28。**EVAS 的低达标率主要来自执行语义和可转换表达式的缺口，不能用一个“数值精度不够”解释。** OpenVAF-R＋ngspice 的失败集中在事件编译；Gnucap 的失败集中在零点事件接受、持续复位和缺少 `idtmod`。Spectre 在当前 31 条件两档均满足有限观测判据。这里分析正确性与设置敏感性，没有进行运行速度排名。

基于固定的 [248 条结果](results/MATRIX.md)和[首轮诊断](../dvs2-starter-pilot/DIAGNOSIS.md)，本次在 thu-sui 追加 **15 个诊断探针：13 次电路启动、2 次仅编译 MIR**；另有 3 次生成 C++ 的编译，合计 5 次编译调用。无超时、无重试、无仿真器修复。变体与原始输入分开归档，没有替换原成绩。

## 2. EVAS 的原因

### 2.1 事件检测先消耗状态，后续接受却可能拒绝它

部署 `rust_core/src/event.rs:157` 的检测器在表达式进入容差带时产生候选，并登记 `last_cross_times`。`rust_core/src/program.rs:1324` 随后用过零方向复核；若此时仍在过零前，会丢弃候选，却未撤销此前登记的状态。真正过零时可能已经没有新候选，离开容差带时又可能被时间去重抑制。

这不是每次都失败：波形斜率、步长和浮点落点决定是否经过有问题的路径。因此“更细”有时反而暴露漏触发。

| 本轮单因素对照 | 结果 |
| --- | --- |
| E1 对齐条件：0.1 ns 步长，恢复基础档数值容差 | 仍违反事件历史 |
| 同条件：1 ns 步长，使用细化档数值容差 | 达标 |
| E1 对齐细化档：只把 cross 表达式容差改为 0 | 达标 |
| E1 平移基础档：只把 cross 表达式容差改为 0 | 达标 |
| E2 低电平启动细化档：只把 cross 表达式容差改为 0 | 达标 |

旧 V3/V4 已有同类单因素对照和部署二进制检测器重放。本轮把机制证据扩展到 E1/E2；C1 等其余条件的逐个内部轨迹尚未完整取得，保留同源机制判断的边界。零表达式容差只用于定位，不能据此宣布通用修复或把原合同改成容易通过的版本。

### 2.2 S1：三条贡献被最后一次写覆盖

合同要求同一支路满足 `vout = g1*u + g2*v + bias`。原模型把三个加数分别写成三条 `<+`。

- 原 EVAS 输出保持最后一项 `bias`，两条件两档最大误差约 0.7 V。
- **只调整三条语句的顺序**，让 `g2*v` 位于最后，整条输出恰好等于 `g2*v`，最大拟合残差为 0。
- **只合并为一条相加的贡献**，同一物理公式满足原判据，最大解析误差约 `6.73e-14 V`。

部署 `simulator/backend.py:10705` 把每条贡献分别收集成静态线性操作，`rust_core/src/expr.rs:22` 逐项执行直接节点赋值。日志确认 S1 有三条连续线性操作。结果与“最后一次写覆盖前面的贡献”吻合。

值得区分：`simulator/stmt_ir.py:1668` 的另一条 body-IR 路径已有同支路相加处理；当前连续线性路径仍直接覆盖。这说明问题包括**不同执行路径对同一语言语义的处理不一致**，不能只在一个模型生成模板里修补。

### 2.3 V7：贡献关系被当作有限次数的旧值代入

线性模型要求每个时刻满足 `y = u + k*y`，独立解为 `y = u/(1-k)`。旧归因已核对整个基础档主条件：EVAS 轨迹与“两次旧值代入”的递推吻合到约 `2.22e-16 V`，初始正确值 0.4 V 实际为 0.3 V。

对于单调三次关系 `y + λ*y³ = u`，唯一解并不保证直接代入 `y ← u − λ*y³` 收敛。因此这些失败不能靠加密时间步长修正：每个时刻的代数关系应当被求解到残差要求，无法求解时应明确失败。

上述结论针对当前命中的路径；部署源码其他路径存在迭代刷新，不等于 EVAS 完全没有任何迭代机制。详细递推、初态及源码边界沿用[首轮 V7 证据](../dvs2-starter-pilot/DIAGNOSIS.md#34-v7连续贡献是约束不能靠跨时间步逐渐接近)。

### 2.4 有些功能存在，但合法调用形式未被当前路径接收

| 条件 | 已确认的拒绝位置 | 解释 |
| --- | --- | --- |
| V5 | parser 读完第二个 timer 参数便要求右括号 | 当前版本不接收本卡三参数 timer，尚未进入运行阶段 |
| v6-standard、C2 | laplace 收集器拒绝双节点输入 `V(vin,vref)` | 旧诊断中参考接地时改为单节点访问可以执行；标准数组语法本身已修正 |
| D1 自由/复位积分 | 连续体无法 lowering | 通用贡献表达式不能直接编码该 idt；赋值专用路径又拒绝第三参数 |

D1 的新增对照把 `idt` 移入 real 变量赋值：保留三个参数仍报 `continuous_body_not_lowered`；自由积分条件中再移除恒为零的第三参数后可执行并达标。部署 `stmt_ir.py:1296` 的赋值专用编码明确拒绝 `len(args)>2`。

因此 D1 的证据支持“该合法调用形式/复位接口未打通”，不支持“EVAS 所有积分都不支持”。D2 的相位积分在原矩阵中本来就两档达标。

## 3. OpenVAF-R＋ngspice 为什么只有 16/31

两档都剩 15 个未达标条件，可拆成 **9 个编译拒绝、5 个事件语义错误、1 个超时**。主要问题发生在固定 OpenVAF-R 编译链路，不能把它们笼统归到 ngspice 数值求解。

| 类别 | 条件 | 机制与证据 |
| --- | --- | --- |
| 组合事件解析拒绝，9 个 | V4 两个、E2 三个、C1 三个、C2 一个 | `cross(...) or cross(...)` 在 `or` 处被拒绝；尚未生成交给 ngspice 的模型 |
| 事件门控丢失，5 个 | V3 一个、E1 三个、D1-reset 一个 | 普通 cross 事件体直接进入求值路径；发布源码与实际编译器 MIR 相互印证 |
| timer 相关超时，1 个 | V5 | 旧 MIR 已确认时间门控丢失；工作点迭代停滞与该机制一致，尚未证明是超时的唯一原因 |

本轮使用部署编译器重新导出了两份 MIR：

- **E1：** 两个计数器的加一和存储位于求值路径中，没有输入电压过零门控。原波形在 t=0 已达到约 1216 V，终点约 2008 V，而合同输出量级为 0–0.2 V。这是模型语义改变，远大于毫伏级数值误差。
- **D1-reset：** 两个事件赋值最终把 `reset_flag` 化为常数 0；MIR 中存储的是零，且求值输入不再依赖 `rst`。所以复位信号为高时输出仍沿自由积分轨迹变化。这里尚不能评价正确传入复位参数后的 ngspice 积分算子，因为复位在前端已丢失。

部署版本由固定镜像和工件标识为 OpenVAF-R v24.0.2mob；自身版本命令输出 `unknown`。这些结论不扩展到其他 OpenVAF 分支或整个 ngspice 的功能范围。该链路在当前静态关系、隐式反馈、标准低通、自由积分、相位及贡献相加条件上表现较好。

## 4. Gnucap 为什么基础档 17/31、细化档 16/31

基础档未达标的 14 个条件包括：11 个事件条件、1 个复位积分条件和 2 个相位模型编译拒绝；细化档另增加 C2 的事件失败。默认 `short` 造成的旧低通问题已通过事先固定的新设置解决，本轮不把它继续算作低通能力缺失。

### 4.1 精确过零时漏接受；实例顺序差异可由舍入触发

实际生成 C++ 的 `cross::tr_review` 只有在相邻值乘积严格 `<0` 时排入接受队列。`负数 → 0 → 正数` 的两次乘积都是 0，事件可能遗漏；`tr_advance` 后续又推进了符号状态。时间和表达式容差在这些生成函数中还被标成未完成处理。

本轮给生成 C++ 加日志，所有 4 次插桩运行的**导出波形与原始文件逐字节相同**，因此日志没有改变被解释的结果。

| 诊断点 | 实际轨迹 | 结果 |
| --- | --- | --- |
| C1 主条件，A 的首次采样，0.5 µs | 表达式落在精确 0，下一次由 0 到正数 | 没有有效 accept，漏采样 |
| C1 交换声明顺序，同一次采样 | 表达式为 `−5.55e-17`，下一次到正数 | 符号乘积为负，有 accept，条件达标 |
| C2 细化档，第三次采样，3.5 µs | 表达式落在精确 0，随后变正 | 漏掉本次采样，输出保持上一采样值 |

这直接解释了两个新现象：**换实例顺序改变结果**，以及**低通中间节点误差更小，整个滤波加采样电路却失败**。当前证据支持零点处理对舍入/调度敏感，不应直接推断为实例状态串扰。旧 V3/V4 已有同类插桩证据；未对全部 E1/E2 条件逐个插桩，不能把家族归类当作每个内部事件都已追踪。

### 4.2 D1-reset：把持续复位表现成一次脉冲复位

本例 `flag=1` 的区间约为 1.5–2.5 µs，积分输出应一直保持初值 0.25 V。原波形中的标志正确，但输出在 2 µs 达到 0.2625 V，偏离 12.5 mV。

本轮日志显示复位接口只在约 1.5 µs 传入 1、约 2.500002 µs 传入 0；发布实现 `mgsim/d_va_filter.cc` 在 `tr_advance` 消耗 `_reset` 并立即清零，然后继续积分。复位保持区间的波形与“仅在 1.5 µs 重置一次、随后继续积分”的公式吻合，最大拟合残差约 `1.31e-14 V`。

因此它与 OpenVAF 的 D1 失败不同：OpenVAF 丢失复位状态；Gnucap 已得到正确状态，但持续复位没有维持输出。所需的保持语义由 [Verilog-AMS LRM 2.4 §4.5.4](https://www.accellera.org/images/downloads/standards/v-ams/VAMS-LRM-2-4.pdf)明确规定，测试合同没有把脉冲复位误当成持续复位。

### 4.3 D2：在当前 modelgen 中未解析 idtmod

两个 D2 条件共四条配置都在 modelgen 阶段报告 `unresolved symbol: idtmod`。这是明确的前端拒绝，不是积分精度不足。不能由此否定 Gnucap 已通过的自由积分或标准低通。

## 5. 对 EVAS 改进的含义

当前证据支持按根因修复共用实现，而不是逐例改写模型或选择有利步长：

1. **事件接受与状态提交：** 先保住候选、拒绝、接受和去重的一致性。回归应覆盖原始合同、相位平移、斜率、细步长、启动状态和多个实例；不把零容差诊断变体当作修复。
2. **支路贡献与约束：** 统一 body-IR 与静态线性路径的累加语义；保证语句交换顺序不改变同一公式。隐式关系需有残差控制与明确的无法求解反馈。
3. **动态算子接口：** 逐项补齐三参数 timer、双节点 laplace 输入和 idt 复位；同一功能的不同合法表达式应进入一致语义路径。

这里是修复优先级及其验收依据，本轮没有修改 EVAS。后续修复使用新的代码/运行身份，固定 0.8.7 的结果继续保留。

还要区分比较范围：这 31 个条件刻意包含事件、复位、状态和组合行为，多条条件共用同一特性。因此它能揭示这些缺口，不能据总分推导工业电路覆盖率或整个软件的成熟度。正式观察资格仍为 I。

# 分数闭环与校准扩展

本路线实现批准规格 #150 的三个独立工程目标。任务归属 `benchmark/tasks/v3-calibration-*/`，固定后端沿用 `v2_runtime.py` 和 circuit harness。r9作者矩阵曾完成，但最终独立审查发现稳定窗口早于公开15us恢复期限。r10保持15us合同，延长驻留、推迟物理窗口并单独检查实际事件期限；20个新PLL实际条件已完成，D2/D3用新checker重分析原24个条件。最终44个条件中，14个正确实现条件通过，15种语义错版的30个条件全部被拒绝。旧证据保留，不替代新版本。没有模型试做。发布与合并由主协调者另行处理。

| 设计单元 | 任务 | 必须实际观察的行为 |
| --- | --- | --- |
| D1 | fractional-pll | 实际 DCO 上升沿组成 N/N+1 feedback，平均分频和输出频比、相位、复位及模式切换 |
| D2 | continuous-offset | 零输入窗口更新实际执行码，慢变差分失调残差与正常信号保留，停启、限幅与恢复 |
| D3 | common-mode-servo | 实际双路输出的共模误差和差模增益同时合格，停启、限幅与恢复 |

来源302提供分数闭环主题，但旧toggle计数合同不直接继承。306与369分别提供静态trim和有符号持续校准，已合并为D2的同一执行合同。390对应D3。现有v2 fine-TDC仍保留原身份。以上新环境均为自编行为合成前端，没有器件数据或开源同题复验资格。旧来源快照及许可边界随题保存，未复制其实现。

`build_tasks.py` 生成公开工程、私有台架、参考解、不同的正确算法以及编译型语义错版；重新生成后必须重新校准身份。`manifest.json` 登记完整变体与预期，不把 pending 当作实际结果。`test_checker.py` 通过候选实际输出 seam 验证共模合格但差模损坏应被拒绝；它不运行仿真。

作者校准先执行原 `solution/solve.sh` 的产物。随后每个候选在两个固定台架执行，错版必须实际编译并获得 graded 行为失败，编译失败不能证明 checker 敏感。完整日志、波形和恢复状态留在忽略的runs；精简结论需要保留候选、checker、条件、后端与实际波形身份。总Spectre并发由主协调者分配，本路线最多一在途job。

阈值根据公开用途设定。差分残差12mV覆盖2mV量化步长、执行增益变化与校准间隔内慢变偏置；共模8mV覆盖相同量化与持续伺服建立。PLL窗口平均计数允许边界截断一个间隔，但逐间隔只能N/N+1；相位接受可预测分数波动，不要求参考序列逐位一致。这些阈值在最终真实正例和不同正确实现中均有数值裕量，见下表。

固定执行后端为 Spectre 21.1.0.509.isr12，r9历史证据见[r9作者校准报告](author-calibration-r9.json)。D1在150us加入运行中±2MHz频率扰动、175us撤除，原频比和相位阈值不变；从实际rst检查fb和lock清零，并覆盖全部模式变化的资格撤销。新增reset_feedback与stale_qualification错版均编译成功，分别只因对应判据失败。

每次模式变化、reset释放和扰动都直接检查实际事件后15us的资格状态，另留2.2ns有限事件/过渡数值裕量；稳态物理窗口从期限之后开始。实际14us恢复版本两个条件均通过；16us版本物理频相仍合格，恢复期限和随后窗口的资格覆盖判据均拒绝该超时。

D2/D3的电路、候选、刺激、解析器和物理合同保持原字节，只有共享checker新增D1分支检查。为统一交付版本，[归档重分析报告](analog-reanalysis.json)逐一验证原执行报告与波形摘要，用新checker重算24个条件，每项checks和原执行结果完全相同。报告同时保留旧execution criteria与新analysis身份；这24条是原仿真重分析，不能计为新增仿真。

先前68个实际条件完整保留，其中7个未评分。r8旧PLL的12个条件和r9的16个PLL条件均转为历史，不能替代修复后版本的20条新执行。早期编译/checker错误、旧判据和冗余同源别名均不增加有效负例数量；未执行的准备目录不算仿真次数。[r8报告](author-calibration-r8.json)保留复用前资产身份。原始归档和波形留在忽略的runs；精简报告保存job、报告摘要、候选、checker、台架、支持源码、波形和后端身份。当前完成的是作者校准，发布、合并和关闭#150由主协调者在独立审查后处理。

正确实现的非法分频计数、资格撤销/保持失败比例、停用码跨度、复位码及越轨误差均为零；两类模拟控制确实到达64码限幅，并在后续窗口恢复。十个独立checker单元测试覆盖差模损坏、合法有限码沿、非法半码、非唯一合法分频序列、稳定但错误的平均相位、reset假反馈、遗漏重配资格撤销，以及14us合法恢复与16us超时。它们不计入实际仿真次数。

[交付核对](acceptance-map.md)逐项映射三个设计单元，[来源身份](source-provenance.json)保存302、306、369、390的固定资产摘要。准备器执行参考脚本后封存真实候选；收集器校验返回报告摘要、冻结候选及criteria身份，保留每次实际尝试，不把编译或checker错误计入语义负例。

# C1 单一实际回调与 #79 首步残差

这是现有 Spectre 原始输出的零新增执行重析。原判据、严格逐点失败及指定查询覆盖要求保留。
原始材料均为 local-only；本页的有限数值结论不证明连续域误差上界。

## C1：一个实际时刻贯穿全部消费者

从每次插桩日志的 `%.20e $abstime` 读取唯一回调，回读一次为 binary64 的 `te`。
不用 PSF 十进制 token 推断回调，不按节点或行拟合时刻。以同一个 `te` 定义前后态、
`sample=te/(2 µs)`、`stamp=te/(1 µs)` 和
`y=sample*clip((t-te-0.25 µs)/(1 µs),0,1)`，同时检查全部九个输出。
事件窗口仍为 1 ps，sample/stamp 预算仍为 0.1 µV，其他输出仍为 1 µV。

| 既有配置 | 全部原生行 | 同一 te 的全消费者判决 | 原指定行缺失 |
| --- | ---: | --- | ---: |
| 原 C1 | 171 | P | 1 / 106 |
| 相邻查询 | 108 | P | 2 / 7 |
| 仅 cross 时间容差 1e-18 | 97 | P | 3 / 7 |
| 仅 cross 表达式容差 1e-18 | 97 | P | 2 / 7 |
| 移除 strobe 控制 | 92 | P | 104 / 原 106 |

五种配置的回调均在原 1 ps 窗口内；最大输出误差为 1.448e-15 V。
每对原模型和插桩模型完整 PSF 只差日期头，全部保存时间和数值逐字节相同。
[逐项数据](evidence/c1-shared-callback.json)保留所有缺失时间、每节点最大误差、日志和 PSF hash。
移除 strobe 的控制没有新指定集，故仍报告对原 C1 查询集的覆盖，不能以原生行取代它。

这些观测支持原工程窗口内存在一条共享、持久的事件历史；没有逐点拼接不同历史。
它们不使 EVAS 的精确根与原 Spectre 名义查询的阶段相同：原严格 C1 仍为 F，
五个配置的原指定查询覆盖仍为 I，也未取得完整工程资格 P。

## #79：有限轨迹上的首步偏移

复用 d7 的原 `original-interior-sparse` PSF（SHA256
`d4f29f65b8632b06a2f7eece04fa573e81a1efc395d28c16bd663cc895b78d6f`），
不新增运行。在 t=1 s，count=1、z=0.5000000000000001 V；下一保存时刻
1.000000001048621 s 的 z 仍相同。随后直到 3 s 的 427 条 count=1 行中，
`z-(1-t/2)` 首项为 5.243105949404026e-10 V，相对该项的最大漂移为
4.163336342344337e-16 V。

该偏移把线性轨迹的 `z+0.5=0` 外推到 3 s 后约 1.04862119 ns。
第一条 count=2 保存行位于 3.000000001098621 s，比这个外推点晚约 0.05 ns。
它是保存的状态行，不能仅凭 PSF 称为精确实际 callback。
[紧凑数据](evidence/pr79-first-step-residual.json)保留原始端点和计算量。

事实是 3 s 保存行仍为 count=1、z=-0.4999999994756893 V；原 stop=3 的阶段差仍为 F。
持久偏移解释这段有限轨迹的阈值延迟，但不识别专有积分或重启公式，也不证明步内轨迹。
这个诊断允许继续到 3 s 之后，不能替代原 stop=3 要求或其原 checker。

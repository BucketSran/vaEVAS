## 为什么符合语言方向的修改仍造成大量失败

[Verilog-AMS LRM 2.4](https://www.accellera.org/images/downloads/standards/v-ams/VAMS-LRM-2-4.pdf)
§3.2 规定 real 的 64 位双精度存储；§4.2.2–4.2.3 规定表达式结合与求值顺序；
§5.2–5.3 规定 analog 内的顺序执行。项目的
[ADR-006](../../../../../evas/docs/development/DECISIONS.md#adr-006)
进一步明确逐次 RN、源码位置绑定、同次逻辑发生及共同提交/回退的实现合同。
这些条款支持设计方向，不能单独证明每个 IR33 数值边界选择和全部消费者实现都已符合标准。
物理根、连续方程与程序 real 的边界须按[数学合同](../../../../../evas/docs/math/events.md#program-real-procedure-contract)分别判断。

大量失败来自共享表示和执行方式改变后，消费者、测试和验收尚未一起迁移：

1. **旧参考把程序 real 当成精确实数。** 设 `real a=9007199254740992.0`，先存储 `a=a+1` 再算
   `a-9007199254740992.0`，结果为 0。旧代数内联若保留精确的 `+1`，会得到 1。旧有理数 oracle 对物理
   积分仍可能正确，对经过 real 存储的值却可能不再正确。提高参考精度不能修正错误语义。
2. **程序位置现在属于值的身份。** `snap=a` 放在 `a=a+1` 前后读取不同值；把它当全局别名
   延后展开会晚读状态。新增 `RealLocal`、`RealBoundary`、过程帧和来源 owner 后，仍只识别
   旧表达式树的准入、静态查询、初始化和历史消费者出现遗漏。静态查询丢失输入依赖已由
   独立 Python 探针复现，这是实现错误。
3. **求解器尚未完全接通新数值表示。** 逐次舍入后的映射不再是原来的光滑函数。
   旧 Jacobian、仿射投影和唯一性证明不能直接跨越 RN 边界。`nonfinite Jacobian` 表示当前
   证明路径失败，不证明原物理模型无解；也不能跳过证明、仅凭名义解放行。
4. **初始化与记录变成显式执行。** 原 `State.initial`、事件数量、数组下标和整批快照断言
   有的检查的是旧内部布局。新增 initial_step 记录不等于多执行一次物理事件。
   但整批 t=0 快照与分阶段源码快照仍有契约冲突，不能一律过滤记录后宣布正确。
5. **新路径消耗和旧规模假设不同。** 绑定 DAG 可能避免旧指数展开；反过来，全程序审核、
   无关驱动扫描和重复证明可能增加工作。实际超预算必须审计收费来源，不能靠调高上限消除失败。

688 个剩余方法在 PR #243 前的固定 CI 通过，另 3 个当时尚不存在；全部在 PR #243 的
开发基线中已失败。这证明失败随 IR33 集成进入主线，不证明 688 个旧 oracle 都正确。
[PR #243](https://github.com/BucketSran/vaEVAS/pull/243) 本身明确说明消费者迁移和完整验收尚未完成，
用户当时授权合入带已知失败的开发基线。不能把“接受了正确的设计方向”解释成“实现已完成”。

最终 CI 相比上一轮还有三个同为非通过的方法改变了首个阻断：SI-01、两项 sample-edge-filter
从初始化拒绝推进到预算耗尽。本审计使用最终错误，没有沿用旧分类掩盖这些变化。

## 按依赖和风险安排修复

下面是下一阶段计划，尚未执行。一次交付处理一个完整行为及其消费者，测试迁移随对应合同进行。
优先级表示处理顺序；不能把一组方法数量当成该批必定消除的失败数。

### 先固定判据与安全边界

- 裁定两项 t=0 记录快照争议，明确 initial_step 与零时刻 timer 的阶段、before/after 和输出观察关系。
  保留原物理状态、事件次数与时刻要求；给记录投影增加缺失、重复、错误顺序和伪造快照负控。
- 对舍入、真实 source band、不同实例或不同发生身份的负控，分别建立程序值与物理域参考。
  不把原 133 项审计中的家族控制当成每个原模型数值验收。
- 把既有下降根前 1 ULP 的普通保持反例作为必须保留的安全回归。它在首批验收时已记录，
  并不在这 691 个原方法形成的完整缺陷范围之内；本清单不能充当全部已知问题清单。

验收：每个拟修改断言有独立答案、原失败和定向错误控制；有冲突的条款先形成明确决定。
未能裁定的负控保持开放，不能改为无条件接受或删除。

### 第一批：贯通过程帧与输入依赖，恢复有限的已支持路径

优先处理 `RealLocal`/`RealBoundary` 的静态依赖遍历、readout/guard 资格、事件来源 owner、
StepBoundCapture 提供者、closed initial math 分派及普通状态路径。复用 #229、#231、#232
所记录的迁移职责，不新增一套全局符号内联来绕过过程帧。

代表问题包括静态查询把 `local=V(u,r)` 的输入依赖变成空集、case 互斥臂捕获身份冲突、
闭合 `pow(16,1/4)` 被误送入物理算子准入、直接电压 integer 转换漏新节点。

验收：等价直接/局部写法、语句前后快照、同模块多实例、参数变体和失败重试均有独立结果；
查询不提交状态；候选帧、历史、证明及输出一起回退；真实预算仍累计收费。
先复现最小原失败，再修复，再运行完整原请求及受影响消费者。

### 第二批：程序 RN 与数值证明衔接

分开处理三个域：可证明单一舍入值、跨舍入格的真实输入域、含舍入关系的隐式反馈。
单值证书保存舍入后的 binary64 值；多值域继续传播整个包围；一般反馈必须另证存在性、
唯一性和输出误差。不得把原平滑 Jacobian 证书、精确分数谱系或代表点当作这些证明。

验收：半格和邻接浮点数、正负缩放、除法与倒数乘法区别、真正 source_errors、误差放大及
不唯一/无解负控。只恢复已证明的有限子集，未支持的一般 rounded feedback 继续明确拒绝。
原容差和预算不变，不能用缩小模型、缩短时长或丢观察点替代原请求。

### 第三批：初始化、复位、采样与连续历史组合

在前两批提供可靠帧及值域后，处理零时刻普通赋值/initial_step/timer 的日程与记录，
以及 idt、transition、laplace、隐式动力学、物理根和连续历史重启。
关联 #226、#227、#230，继续保留同引擎失败重试、未受影响历史和原根时间不确定性。

验收：同模型稀疏/稠密查询、边界前后浮点值、复位前后积分面积、相邻但不同物理事件、
零 timer、停止边界和跨实例组合。修复记录访问后继续执行原方法全部数值断言，
新暴露的旧缺陷另记，不能把“首个断言已过”当成方法通过。

### 第四批：预算、规模与诊断协议

先处理有源码计费公式和独立算式支持的无关驱动二次开销，再调查 100000 前端审核帽及
复杂历史预算。逐类给出工作账户和原请求前后比较，保留 sticky exhaustion、共享上限和
失败后不返还费用。DAG 替代指数内联后，旧成本断言只在确认实际收费模型后迁移。

诊断同时检查 kind、category、origin、阶段及消费者。恢复 `$rdist_normal` 的明确 unsupported
诊断；跨 kind 的变化不能仅改正则。验收包括匹配正控、资源上限负控和完整错误协议。

### 最后收齐测试迁移与能力证据

316 项测试预期问题按上述行为批次处理，包括初始化记录、IR 布局、源码顺序、舍入参考及
资源图形变化。每项保留原测试身份和失败收据，标明更新的是哪项义务及独立依据。
运行完整方法所有子例；恢复后的负控必须仍能检出原保护目标的定向错误。

修复批次的发布条件为：原通过集无新增回退、受影响完整方法及后置断言通过、共同消费者和
同引擎回退检查通过、固定候选完整 CI 逐方法比较、独立 Spec/Standards 审查闭合。
capability 按具体模型、配置、版本登记新证据，不能按 CI 方法数或节点依赖自动提升支持成绩。
剩余未决项逐条保留；未获得同源 Spectre 执行的项目继续列入待跑，不宣称兼容性资格。

## 本轮验证及边界

本轮验证对象是审计材料和分类，不是新的模拟器实现。检查覆盖集合、唯一身份、957 条原始
记录归属、固定源码及模块哈希、四份审查输入/输出一致、节点存在性和生成映射。
复用已完成的 CI；新探针仅含记录在收据中的 Python 编译/查询及独立算术，没有新数值内核或
Spectre 执行。分类不修改任何原结果；完整 CI 仍为 failure。

105 项实现问题也不是 105 个独立修复任务。它们大量共享过程帧、准入及历史消费者；
269 项缺证需要按表中原程序和义务补证。先把这些边界说清楚，才能评估下一批修复是否有效。

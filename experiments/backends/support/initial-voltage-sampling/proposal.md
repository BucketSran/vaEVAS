# 初始电压采样的有限扩展提案

本提案对应 Issue #214 第08项。当前只完成设计和独立红基线，没有修改初始化实现，也没有执行五个目标原件。建议先支持能认证为精确浮点单点的 `initial_step` 采样。一般非点初态留给后续接口改造。PR #208 的草稿状态不变。

## 首个切片只安装经过认证的单点

接受 real 状态读取零时刻电压、仿射组合和已有条件选择中的电压臂。保留顺序赋值、非零参考节点和所有分支的结构检查。内部电压只有在现有完整贡献闭包已经认证为单点时才可读取。采样后保持状态，输入随后变化不能重新采样。

选定表达式的有限区间必须满足 `lo == hi`，才可将该端点安装为精确初态。不能用普通浮点求值结果、中点或名义输入替代认证。精确的输入也不保证结果可精确表示，例如两个 binary64 输入 `0.1` 和 `0.2` 的数学和不能由一个 binary64 数精确表示。即使结果在数学上唯一，只要当前包围仍有宽度，首个切片就保守拒绝。

非点采样值、无法确定的选择边界、非线性电压运算和未认证历史保持拒绝。未驱动、矛盾、奇异或循环依赖复用现有拒绝路径。integer 沿用逐次赋值的整型及 signed32 范围证明，不新增隐式 real 转 integer。`$abstime`、普通局部量绑定、声明初值和零 timer 的 bootstrap 语义另有责任，不因放开电压采样一并接受。这些是 EVAS 的能力边界，不表示相关语言写法非法。

## 直接复用现有解析和认证路径

`instance_compiler.py::initialize_states` 已通过符号环境保留源码顺序，`initial_select` 已保留条件来源。首个切片只需调整常量臂准入，不应另建初始化解释器。

`initialization_nodes.rs` 已按需解析电压与初态依赖，并在安装前使用全部原贡献重做认证。保留其256未知量、128依赖深度和100000工作步上限。`initialization.rs` 继续先收齐候选结果，全部成功后才安装 `State.initial`。失败时尚未创建事件模型、日程、算子历史或接受帧。

数值认证优先复用 `interval.rs` 的精确加法与乘积检查，以及现有条件选择认证。`expression::evaluate().value` 本身不是包围证明。首个切片保留 `State.initial` 和下游 exact f64 假设；本提案保持 IR24，使用现有表达式编码，不增加字段。运行期诊断保证实例和状态身份；仅在已有元数据提供位置时附源码位置，例如 `Select.Origin`。普通 `Affine` 初值和 `State` 没有必填源码位置字段，不能承诺逐行定位。

## 五个原件的零时刻输入可表示为点

以下值来自固定 `891fa1b9` 的公共 SCS 解析和原 VA 赋值。表中的小数表示解析后的 binary64 数，不把十进制文本解释为无限精度实数。相关初始驱动都有定义；推导出的显式初值均可由现有 f64 表示。这个结论尚未经过新增采样运行路径验证。

| 原件 | 原始显式初值 | 独立限制 |
| --- | --- | --- |
| 003 pipeline stage | `vin_s=0`，`vres_level=binary64(0.9)/2`，`d1_level=d0_level=0`；`VSS=0`，三个 drive 按源码顺序得到对应电平 | 除2是精确二进制缩放；后续 ADC 运算、事件赋值和 transition 仍需完整原件验收 |
| 011 PFD | `up_state=dn_state=0`，`up_level=dn_level=binary64(0.1)` | `VSS` 实际为0.1，不能默认地电位；后续 up/dn 条件与写入顺序未验收 |
| 045 comparator | `VINP=0.35 < VINN=0.47`，选择 `VSS=0`，故 `out_level=0` | 初始选择确定；后续 cross 中的电压臂和 transition 是独立消费者 |
| 072 sample hold | `sampled=binary64(0.05)`，`sample_t=-1`，`armed=0` | 普通 `vh/vl` 名字、延时 timer、后续重采样和 transition 不属于本切片 |
| 096 pipeline chain | 三个 code 为0，`vin_s=0`，两个 residue 为 `binary64(0.9)/2`，八个 bit 电平由 `VSS=0` 得到0 | 后续两级整数判定、局部量和多输出仍可能暴露其他阻塞 |

五个原件没有运行，不能把上述初值结论换算为新增通过数。原 VA、刺激、初态、checker、输出网格、精度与资源预算均不变。

## 独立夹具已有27项基线

最小可提交材料为本提案、[运行器](fixtures/runner.py)、[原基线收据](fixtures/baseline.json)和[检查器负控收据](fixtures/review-controls.json)。模型和 Fraction 独立答案都在运行器中，不需要提交临时源码快照、大 JSON 或二进制。

冻结编译器为 `891fa1b9`，实际执行的是 release 内核，SHA256 为 `4e7927e14e7ce22789b0563d67a847ec8215c88e41c24115313e88f9cca656d8`。27项中17项满足当前合同，10项留下红基线。红基线包括9个公开编译入口拒绝，以及1个 raw IR 内核拒绝，后者证明限制也存在于 Rust。

原27项收据保持原运行器哈希和执行身份，后续修订另留收据。运行器的公开入口和 raw IR 检查现在共用 `answers_match`，先核对完整波形长度，再比较数值。每次运行还将真实成功控制的波形改为空、只剩一点和缺最后一点，检查三种错误都被拒绝；完整控制仍通过。根目录入口只委托这个唯一运行器。

17项包含两个已有接受控制、十四个拒绝控制和一个公开编译对象的失败后重试控制。部分负例仍在编译阶段停止，因此不能证明放开采样后运行期仍能正确拒绝不确定值。公开重试启动了独立内核进程，也不能证明同一内核实例的回退。来源提交未证实的旧 debug 单元测试不计入主要证据。

正例覆盖非零参考、输入改变后保持、仿射组合、选择边界、顺序赋值、timer(0)、保持状态 timer、transition 和 idt。负例覆盖不确定采样、下游放大、不可精确表示的和、未驱动输入、状态电压循环及整数边界。

## 非点初态需要后续明确传递包围

若以后支持非点初态，`initial_nodes::resolve` 的 `Vec<f64>` 不再够用。需要传递初态值、包围和证明，并逐个接通 `EventModel`、初态不变性证明、timer 日程、零时刻 bootstrap、算子历史、连续与隐式路径、`Frame.state_bounds` 及输出认证。任何代表值都不能取代这些包围。

这项后续工作必须证明误差经过保持、事件写入、算子历史及电压放大后仍满足原预算，并验证失败不污染状态、日程或历史。首个单点切片不引入这项接口改造。

## 外壳与设置

EVAS 直接使用 Spectre 批次的同字节 SCS 和 VA，以固定 --spectre-strict 入口运行；不把其 reltol 等请求当作已经实现的 SPICE 误差控制。

ngspice 的模型端口、每实例参数和 PWL 物理刺激保持一致，保存全部输入、中间节点及输出；以 option 命令记录可回显的设置，保留正常工作点，不用 UIC，不做 linearize。无参数 option 的行为依据[官方手册 §13.5.54](https://ngspice.sourceforge.io/docs/ngspice-manual.pdf)。编译多模块时不拆解、删除或重写源文件。

Gnucap 所有原来连接数值节点 0 的 DUT 端口映射为 bench_ref，由理想零伏源接地并保存该节点。原本变化的 vref 输入保持不变。统一 short=1e-9，读取 .options 回显；该设置依据已有标准低通诊断和方法协议，在看到本轮结果前固定，须在全部 31 条件上复验。

其余两档数值请求与 Spectre 输入快照一致：base 的 step/maxstep=1 ns、reltol=1e-5、V abs=1e-8、I abs=1e-12；fine 分别为 0.1 ns、1e-6、1e-9、1e-13。E1 终点 3 us，其余 4 us。各后端的步长和误差控制含义不假定等价。保存工具版本、实际能取得的设置回读、原始日志和导出点。

## 判定与完成

直接复用 Spectre 已冻结 check_results.py、历史解析答案与共同历史检查；不根据新结果调整阈值。每个点检查有限值、信号、时间顺序、起止范围、最大 1.001 ns 观察间隔和输入 1e-7 V 误差。Gnucap 额外检查 bench_ref 确实为 0 V；此检查不删除或修改输出点。

编译失败、运行失败、超时、缺波形、观察不合格、明确数值/历史反例、未决和有限观测达标分别报告。固定目标仍不代表观察预算已取得物理资格，正式 DVS 状态保持 I。

完成标准是每个矩阵单元都有可追溯的执行或复用结论，包含失败；不要求所有方案通过。如果网表适配或输出读取本身存在问题，须保存原尝试，明确改动与新实验身份，再进行必要的有界补充，不能把适配错误归于被测算法。

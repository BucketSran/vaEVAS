## 五类的迁移对应

| 新工程动作 | 优先旧来源 | 可保留的内容 | 必须重新判断的内容 |
| --- | --- | --- | --- |
| 按规格构建模型 | v4 DUT；旧首批5个规格题 | 电路用途、接口、行为线索、公开例子 | 规格是否充分且自洽，是否确为单模块，参考是否正确，checker是否独立 |
| 从数据建立模型 | 旧首批5个动态辨识题；其他模型作为数据产生线索 | 实验组织、记录格式、拟合及留出框架 | 合成数据不能冒充真实电路观测；真实采样级仍从 case-0006 的来源建设 |
| 扩展与集成 | 旧首批5个集成题；健康的 v4 模块作为部件 | 健康模块、可解释接口、固定工程素材 | 必须有真实新增能力和交互，不能把重命名接口或多文件包装当集成 |
| 诊断与修复 | v4 Bugfix；旧首批5个修复题 | 实际 starter、可说明的故障、接口和回归场景 | 真实故障身份、规格缺口、整体重写后的任务价值；多模块另行筛选 |
| 电路测试与表征 | v4 Testbench；旧首批5个验证和5个测量题 | DUT、激励思路、可测性质及语义负例 | 原交付物是不是 VA；如何独立核对激励、测量与违规报告 |

旧首批的5个“改善仿真实现”任务不进入新题型；相关优化探针也不转成收敛或异常耗时题。其余30项仅是可复查来源，不是已接纳30道题。本轮只核对其分类登记，细读了 SAR 流程验证和非重叠时钟激励两份题面，未重新审计整批实现与证据。已使用其中材料的 UVLO 和 ADC 频谱方向继续沿用 case-0009、case-0010。

## 每道题保留什么、重做什么

1. **保留来源链。** 记录旧 task/family、快照、实际文件及必要哈希；同源任务共享 source group。v4-186 与已有 va02 只有类似工程行为，来源记录不同，不能凭名称合并或宣称独立性已证实。
2. **重新写公开规格。** 用端口/参数表、状态或事件表和必要例子讲清工程需求。旧 JSON 是提取线索；新机器合同应从新公开规格生成。示例网表说明连接和用法，不能靠某段 reference 的偶然行为补齐未公开要求。
3. **按任务提供材料。** 规格题给完整要求与使用环境；修复题另给可读 starter 和复现现象；测试题给可读固定 DUT。单模块修复允许整体重写。正式包不照搬旧重复描述和统一三形态配额。
4. **另建可信验收。** 已读包有 checker profile 和固定 deck，但尚未取得、审计并跑通其所指私有 checker。后续应由公开要求独立推导答案，用健康实现及明确负例校准，不能把旧认证或参考波形当现成准入证明。
5. **再固定运行环境。** 根据题目需要选择后端和版本；ngspice 可以独立评分。旧题的 EVAS 限定，以及 Issue #107 较早的统一 Spectre 表述，均不覆盖现行[后端合同](../../README.md#评测方式与题目建设)。不继承禁用某种合法 VA 写法的语言子集要求；正确实现被后端限制挡住时按环境缺陷处理。

后续共同讨论从上面的电路功能总览出发，先决定覆盖哪些工程内容。已有逐题记录保留作实施参考，不要求用户逐项批准规格和checker。

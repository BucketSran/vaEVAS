## 工程目标与拟定交付

恢复一个电源/偏置资格下的同步阶段控制模块。每个时钟上升沿，若复位有效或 supply_ok/bias_ok 无效，则清零；否则依次推进阶段并最终置 ready，同时输出 progress。Agent 可整体重写指定 VA 模块，验收激励和 checker 固定。

本题是同步协议。停钟时把 rst 拉高不能要求输出立即清零，除非另行修改并公开协议。它与 case-0001 的 POR 测试台、case-0009 的多模块 UVLO 修复是不同交付目标。

## 原资产与迁移取舍

来源 v4-1272，family272。实际 starter 忽略 rst，已到 ready 的状态遇到有效复位仍保留。manifest 却标成 progress 比例错误；本卡按实际字节记录，哈希和源码链接见[修复筛选](../../../../migration/v4-repair-screening.md)。故障形成过程未知，不称为真实工程 bug。

原 final_stage 的合法范围只写 finite，允许零会造成除零，也没有解释小于2时 stage2 的用途。建议先讨论默认三级序列，合法参数范围另行确定；不能原样继承这份参数合同。

## 公开材料与独立验收

拟提供故障源码、同步状态表、端口与合法参数表，以及进入 ready 后重新复位的复现。独立 checker 只按外部上升沿更新期望状态，核对阶段顺序、饱和、reset、资格失效、重新释放和 progress 的一致性。

应明确供电/偏置标志在边沿附近变化的采样规则、初态和输出平滑。checker 尚未实现，后端尚未选定。

## 留给同行的问题

这种按拍释放序列是否足够代表实际电源启动控制？现故障仅遗漏一个条件，允许重写后的难度可能很低；建议和去抖、PFD 一起评估基础修复题是否需要全部保留，不预设三题都进入最终集合。

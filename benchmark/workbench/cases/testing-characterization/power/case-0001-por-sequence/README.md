## 工程目标与拟定交付

给定源码可读、不可修改的 POR DUT、固定连接和完整公开规格，Agent 编写 VA 电源激励与复位监控模块，完成上电→欠压→恢复的完整测试流程。每个场景报告实际事件、间隔与合规状态。拟采用固定连接下自定义激励与观测的公开自测方式。

当前是设计草案。DUT 运行环境、引脚合同、数值和输出协议还没冻结，[题面草案](instruction.md)不能直接用于模型评分。这里的完整流程指激励到自动判定，不表示“完整仓库任务”。

## 公开与固定边界

Agent 可修改指定 VA 激励、观测及报告模块；DUT、工程连接、独立 checker 和验收场景固定。只读观测节点不能由候选驱动。驱动端口、供电范围、斜坡/跌落保持时间和场景参数必须在题面公开。

终评可以在公开范围内换斜坡、欠压深度和恢复时刻。这些是同一 Case 的测试条件。若使用违规 DUT 验收监控能力，题面须公开可能出现的违规类别、预期报告和观测窗口；隐藏内容仅是具体参数与实现。

## 独立验收怎样做

1. 从实际电源和控制波形确认测试确实完成了规定的启动、欠压与恢复，不能只信候选日志。
2. 在公开的有效供电域内，独立提取复位保持、断言、释放和重复周期的事件。按已选时间基准计算延迟与容差。
3. 比对候选报告：合规行为不能误报，违规行为不能漏报；没有报告必须区分“检查未执行”和“检查通过”。
4. 先校准 checker：合规的不同动态、过早释放、漏掉欠压重触发、恢复超时、第二轮状态未重置、未完成激励等。负例是出题建议，尚未生成或运行。

原 `response_time` 测的是振荡器事件到 POR 输出，不能静默改称供电阈值到复位。原电路及配套 VA、正常与违规场景都需实际校准，之后才能谈题目难度。

## 本轮需要确认

首先确认采用哪种**延迟定义**：以供电有效门限为起点，更贴近外部电源序列测试；以内部振荡器事件为起点，更接近原脚本。建议先研究外部定义是否足以覆盖目标性质，再决定是否公开内部观测端口。

随后才能固定复位信号及极性、有效电压域、迟滞门限、正常/测试模式、时限、输出格式和数值容差。这些值不由目录建设代替电路核验。

## 工程目标与拟定交付

固定源码可读的 LDO 及启动测试台，Agent 编写 VA 测量模块，报告 t90、建立时间、过冲和有效性状态。先做固定公开测试的限定测量环节；若以后加入激励设计，需要先说明新增工程目标，再决定扩展本题还是另建关联 Case。

原任务要求设计晶体管电路；这里改成测量既有电路。测得 DUT 不满足性能目标，仍可能正确完成测量任务。当前 [题面草案](instruction.md)尚未形成可执行规格。

## 沿用指标时需要精确到什么程度

设目标为 Vtarget，记录窗口为 [0, Tend]，电源斜坡结束为 Tramp。

| 指标 | 拟沿用的原定义 | 容易误判的例子 |
| --- | --- | --- |
| t90 | 最早达到 0.9 Vtarget 且后续记录都不再跌破的时刻；以仿真时间原点计 | 第一次 crossing 后再次跌破，不能仍报第一次 |
| 建立时间 | Tramp 后最早进入 ±2% 带且剩余记录保持带内的时刻，减 Tramp | 先入带后振铃出带，必须重新考虑进入时刻 |
| 过冲 | max(0, 记录峰值 − Vtarget) | 输出未达到目标时不应报告负过冲 |
| 有效性 | 在规定有限窗口内是否有合格测量值 | 窗口末仍不满足条件，不输出虚假的完成时间 |

这不是无限未来的保持保证。原 checker 在离散波形记录上计算，VA 可以采用事件或取样法；正式题必须确定共同语义、端点约定、时间分辨率和允许误差，不能让隐藏 checker 的取样细节成为未公开要求。

## 资产、边界与独立验收

保留原启动场景、反馈、负载与输出电容。Agent 只修改 VA 测量与报告代码，DUT、激励、连接、窗口和 checker 固定。负载电流属于环境；候选只需观测电压与时间。

独立评分从保存的真实波形重算指标，再比较候选报告。原 Python 算法可作为一条参考路径，但应先用已知波形校准：单调建立、先入带再出带、未建立、多峰过冲、窗口端点。随后把校准扩展到真实 DUT 与配套 VA 的实际运行。原 reference.json 或通过记录不证明新题正确。

隐藏场景只能改变公开范围内的电路响应、初态或测试参数。若要检验未建立状态，必须在题面明确它是合法待测情况。输出格式可用明确状态加数值，尚未决定如何编码无穷值或缺失值。

## 本轮需要确认

先确认采用原定义的有限观察窗口语义；再决定以固定取样网格定义结果，还是公开连续事件定义并给离散参考足够容差。这里的选择会影响接口、checker 和跨后端一致性，需要实际波形校准后定稿。

源场景的 1.2 V 目标、21 μs 斜坡结束、70 μs 记录终点已经登记在电路页，但不直接当作新版规格已获批准。行/负载瞬态和休眠/唤醒暂不加入。

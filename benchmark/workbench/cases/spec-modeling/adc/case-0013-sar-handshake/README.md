## 工程目标与拟定交付

Agent 根据公开协议实现一个四位 SAR 前端逻辑模块，依次请求比较、接收决策、更新 DAC 控制，并在下一采样周期发布上一转换字。行为必须依赖实际比较器输入事件；不能直接将模拟输入取整得到 ADC 码。

本卡仍是单模块题。未来若接入固定比较器、DAC 与采样模块，可再形成工程内补模块题；当前没有这个健康工程，不把单模块题称为系统建模。

## 原资产与迁移取舍

v4-186 的 `sarfend_logic_4b` 已有四次握手、测试字覆盖和上一结果发布。其未决 DAC 状态允许 P/M 同为0或1，接受决策后才互补；这一点应保留在公开状态表。参考在 clks 上升时捕获 dtest，但实时读取 test，两者不能混为同一个采样规则。

来源为旧导入222，原工程文件尚未定位。[现有 va02](../../../../../tasks/va02-sar-handshake/SOURCE.md)来自七位 SAR、旧导入243。两者行为相近但不能确认共源；建正式题前先决定保留哪一个或如何区分，避免只因位宽不同增加题数。详细来源见[筛选记录](../../../../migration/v4-spec-screening.md)。

## 公开材料与独立验收

拟给接口、合法比较器脉冲、四步 DAC 状态表、测试字捕获规则和上一结果位映射。交付一个 VA 模块，允许用公开固定连接调试。

独立 checker 从输入事件递推当前步骤，检查请求/应答顺序、全部 DAC 线、结果发布时间、四次后停止以及下一周期重启。先写清首字、转换中断、额外比较脉冲及两比较器输出同高的边界，不能只照抄参考内部指针实现。checker 和配套工程均未建立。

# Example：诊断并修复 ZOOM 九路时序模型

状态：设计稿，2026-10-04。本例有真实生成失败和人工诊断作为材料，但尚未封装为允许工具反馈的修复任务，也没有新的模型修复成绩。

## 工程用途与来源

ZOOM/SAR 仿真需要多路采样、积分、残差和转换时钟协同工作。一个能编译却没有产生脉冲的 VA 发生器，会使整个测试环境失去有效激励。

用途来自课题组 [zoom_sar_multiphase_clock.va](../reference/veriloga/lab/clock_sampling/zoom_sar_multiphase_clock.va)。规格采用已运行初筛题的[完整脉冲日历和参数合同](../tasks/va03-zoom-timing/instruction.md)。

待修复材料来自首轮 `glm-5.3` 的生成答案：两组条件下输出都没有有效边沿，人工小范围修改后两组均通过，见[首轮失败分析](../../experiments/va_screen/RESULTS.md)。**这是实际评测中的生成代码故障，不是已经证实的课题组原始代码故障。**

## 给模型的题面示例

> 下面的 Verilog-A 时钟发生器可以通过编译，但运行所附开发场景时，九路输出均保持低电平。请诊断并修复，使其满足提供的脉冲日历，在合法参数变化下持续产生正确时序。保留模块接口、参数名及默认值。

### 提供什么

| 材料 | 内容 |
| --- | --- |
| `starter.va` | 冻结的失败候选代码，不预先标注错误位置 |
| `timing_spec.md` | `CLOCK_VA` 的九路输出、脉冲起点、宽度、循环次数、合法范围 |
| `public_case.scs` | 一个可复现失败的公开网表及仿真入口 |
| `failure/` | 编译成功的日志、未出现有效脉冲的波形及缺失边沿摘要 |
| 公开 checker | 按相同时间定义报告预期边沿与实际边沿差异 |

沿用模块 `CLOCK_VA(RST,S,SAR,RES,INT,CLK_SAR,ZOOM,CLK_ZOOM,RST_ZOOM)`。这里所有端口都是输出，`RST` 也是发生器产生的信号，不是外部复位输入。所有输出初始低电平，周期性按规格工作。

未来封装时，将原题的功能部分整理为完整 `timing_spec.md`，去掉原有“单次生成、无工具、只返回源码”的执行说明。接口和时序不因换成修复任务而改变。

### 交付物与允许操作

提交修复后的 `/work/dut.va`，可附简短的故障原因与修法。允许查看代码、运行编译/仿真和分析波形；最终只替换候选模型。

允许局部修补或等价重写，不按修改行数给分。解释不能替代行为验收，也不要求候选必须给出某个固定措辞的根因。

不允许修改脉冲规格、把输出固定为预先存储的一组波形，或调整外围参数来掩盖问题。

## Checker：修复已知故障并保持其他条件正确

参考答案来自独立脉冲日历，不从修复后的波形反推。每路信号按事件数量、边沿方向、阈值穿越时刻、脉宽和稳定电平检查，保留初始阶段和跨周期行为。

已有 checker 处理了 `transition` 后的边沿观测。新任务应复用并公开其实际容差与阈值定义，不能拿平滑前的起点直接当作输出电压穿过阈值的时刻。

| 场景 | 作用 |
| --- | --- |
| 原失败参数 | 确认九路时序恢复 |
| 不同正整数脉冲次数 | 避免只修好默认循环次数或只产生单个脉冲 |
| 合法延迟与间隔变化 | 验证参数确实参与时序计算 |
| 不同电平和有限边沿时间 | 检查参数回归和边沿观测 |
| 多个完整周期 | 检查周期重启、累计漂移和多余脉冲 |

同一路脉冲不得重叠或跨入下一主周期，跨输出的有意重叠仍允许。新增隐藏条件先验证满足原合同，并由参考实现通过，然后在模型尝试前冻结。

Checker 校准至少覆盖全零输出、漏掉一组子时钟、周期开始时没有重启，以及固定使用默认参数的错误版本。

## 出题者已有的证据与边界

原始失败提交位于本地 ignored 路径 `runs/va-screen/pilot-20261003-221547/glm/va03-zoom-timing__XfT94nB/agent/dut.va`，相邻 verifier 目录保存评分材料。独立人工诊断位于 `diagnostics/glm-timing-argument-order/`。这些是 local-only 材料，不假设仅克隆仓库即可取得。

已知根因是两个函数的形参顺序与调用不一致，时间值被传给整数计数参数，导致循环不执行。修正顺序即可通过原两组条件。**这一段以及已修复代码不进入候选环境。**

上述证据证明有可复现的代码缺陷和一个已测试的小范围修法，没有证明模型收到反馈后仍修不好，也没有证明新增隐藏条件已经通过。

## 难度假设与落地缺口

本例考查从“编译正常、波形错误”追查调用、类型和事件逻辑。已知修法很小，它更适合作为修复任务的基线。若强模型迅速修好，应如实保留这个结果，再寻找有来源的复杂集成故障。

落地需要把冻结的失败源码和一个公开复现场景整理进任务环境，准备独立回归条件，并校准允许工具反馈的预算。不要把本题的新成绩写回首轮单次生成实验。

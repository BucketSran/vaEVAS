# Benchmark 核心设计文档

这里保存当前采用的设计判断及其理由，供项目成员和电路领域同行阅读。先读
[设计目标与选题判断](design.md)，再按需要查看任务定义和评测规则。

| 文档 | 回答的问题 |
| --- | --- |
| [设计目标与选题判断](design.md) | 为什么建设这个 benchmark？哪些工作值得考察？目前希望同行帮助判断什么？ |
| [五类工程任务](task-types.md) | 每类给定什么、交付什么、允许修改什么、怎样验收？类别之间怎样区分？ |
| [题包格式与验收约定](task-package.md) | instruction、独立接口、公开测试、参考解、checker 与结果文件分别放在哪里？ |
| [评测与复现原则](evaluation.md) | 如何从功能族讨论推进到完整题包？如何选择后端、校准 checker、处理环境缺陷和报告成绩？ |

## 各类材料放在哪里

| 位置 | 保存内容 |
| --- | --- |
| `benchmark/material/draftbench/docs/` | 已采用的共同定义、设计理由和仍待讨论的核心问题 |
| [research/](../research/README.md) | 论文、技术资料和开源工程的阅读结果、适用范围与证据 |
| [draftbench/](../README.md) | 电路功能族、历史设计卡、任务方向及来源关系 |
| [batches/](../batches/README.md) | 实际草稿题包、批次审核清单和逐题去向 |
| [benchmark/tasks/](../../../tasks/benchmark.toml) | 已完成本版审核的正式题集；当前清单为空 |
| [historyref/](../../historyref/README.md) | 原始资料、历史题包和保留原身份的建设记录 |
| GitHub Issues | 工作范围、依赖、验收条件和推进状态 |
| [实验入口](../../../../experiments/README.md) | 已运行实验的协议、结果和证据，不用候选数量代替成绩 |

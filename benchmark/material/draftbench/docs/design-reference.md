# 选题与建模边界参考

本页保存选题依据、模型范围和审核判断的展开说明。日常人工审核看[四个关键问题](design.md)，
Agent 的执行顺序与完成条件看[英文流程](agent-workflow.md)。本页不记录逐题进度。

## 以电路工作决定题目

选题先说明使用场景、信号路径，以及工程师需要保证的电路行为或性能。
通用数学问题附上电路名称不足以成立。数据建模优先考察可观测的动态，例如采样建立、
历史依赖与保持行为；是否存在这些效应，需要原电路表征确认。

电路家族与工程动作分别记录。ADC 便于解释，但覆盖还应包含 ADPLL、电源、放大器、
滤波器等适合当前范围的电路。同一电路可以支撑多个任务，不要求每个家族凑齐全部类别。

当前采用以下五类，完整的输入、交付物与验收边界见[任务定义](task-types.md)。

| 工程动作 | 核心工作 |
| --- | --- |
| 按规格构建模型 | 实现已给出的接口和电路行为要求 |
| 从数据建立模型 | 从表征记录建立能预测新实验的模型 |
| 扩展与集成 | 增加能力，或完成部件的连接与协作 |
| 诊断与修复 | 恢复故障工程应有的行为 |
| 电路测试与表征 | 建立激励、测量指标，或检出规定的违规行为 |

这些类别按本项目的 VA 工程工作划分。CVDP 的任务设计和评测方式是研究参考，
不能把数字 RTL 中某类任务的占比或难度直接套到 VA。材料与比较依据由
[研究专题](../research/README.md)维护。

## 区分两条电路路线

真实电路结合与全 Verilog-A 都可以形成有价值的题目。路线说明行为依据和工程环境，
五类工程动作说明求解者做什么；两者分别记录。同一功能族可以同时保留两条路线。

| 路线 | 典型材料与工作 | 人工审核增加的重点 |
| --- | --- | --- |
| 真实电路结合 | 基于有来源的器件电路建立模型、开发表征仪器，或让 VA 部件与器件电路协作 | 来源版本、工况和观测是否可信；目标现象是否实际存在；抽象与数据是否足以支持任务 |
| 全 Verilog-A | 用 VA 行为模型组成模块、系统和测试环境，完成建模、集成、修复或测试 | 假设与适用范围是否清楚；状态、动态和模块协作是否体现目标电路工作；行为依据是否自洽 |

真实电路结合还需说明运行时是否调用器件电路。固定数据建模使用有来源的完整表征记录，
求解与重验候选未必需要器件仿真；在线表征和混合工程则可能在每次迭代中调用器件电路。
晶体管仿真、硅片实测与行为合成分别标明，不能仅用“真实数据”概括来源。

全 VA 不自动表示 EVAS 兼容，真实电路结合也不自动表示必须用 Spectre。
后端按具体题目选择和验证。题目内容结论与作者执行、独立验收、Agentic 运行的成熟度
分别记录，见[审核分工](evaluation.md#审核分工与分组交付)。EVAS 尚不兼容时，可以先审核
题目价值并用具备条件的后端建设；不能据此宣称已能开展新题包的 Agentic 评测。

## 当前采用哪些边界，为什么

| 已采用的判断 | 理由与影响 |
| --- | --- |
| 聚焦电压域行为模型 | 先建立接口和物理行为边界清楚的题目；不能由一题隐式扩大模型范围 |
| 所有题都结合独立 checker | 验收工程交付物，避免依靠文字解释、参考代码相似度或主观判断给分 |
| 合并测量与验证为电路测试与表征 | 同一个 VA 测试台可承担两者；保留测量准确性与违规检出的不同验收目标 |
| 不设置仿真加速、收敛及异常耗时题 | 本阶段聚焦电路建模与测试工作，这些方向不进入题目计划或修复子类 |
| 允许共享电路资产，保留同源关联 | 多种工作可以发生在同一电路上；统计不能把相关题目当成完全独立的能力证据 |
| 不按文件数、代码长度或预估难度加权 | 工程规模不直接代表完成质量；完整仓库任务可以单列分析 |
| 优先审查旧 benchmark 资产 | 复用已有材料，但重新核对规格、来源和 checker，不继承旧认证为当前验收 |

[电压域行为模型](../../../../GLOSSARY.md#电压域行为模型)限制候选需要建立的行为。
验收环境可以包含由后端求解的晶体管和其他器件；要求候选实现端口电流、输出阻抗及
负载耦合的任务暂不纳入当前范围。出现足够的范围外工程需求后再讨论扩展。

规格建模既可要求功能级理想行为，也可要求指定动态或非理想行为，按工程用途选择。
如果试跑表明功能级题过于简单，再调整后续建设重点，不能事先把所有理想模型都判为无价值。

## 从工程依据提取规格

规格提取的目标是建立可追溯的行为约定。checker 表明当前如何验收，gold 展示一种实现，
故障 baseline 展示待修复的工程。它们都不能独自决定完整需求。原题面及其公开引用资料提供
规范依据，但也可能与工程或测量矛盾，需要保留双方证据并裁决。
[30 题独立重建与对照](../research/spec-extraction-study.md)记录了这些差别。
具体执行顺序由[英文流程](agent-workflow.md#extract-and-review-a-behavior-agreement)维护。

作者在现有 `SOURCE.md` 中区分来源直接支持的事实、推断、主动建模选择和仍未知的条件。
每项独立行为保留输入及相关历史、可观察输出、参考事件或数值、适用条件、误差定义和来源。
例如“关窗时保持输入值”还需要确定关窗参考、复位期间关窗是否有效、释放后的模式；
从参考解看到某个事件写法，不能据此要求所有正确实现采用相同写法。

范围与数值分别按以下职责理解，不能用同一组台架参数代替全部设计判断。

| 要确定的内容 | 应说明什么 | 不能直接推出什么 |
| --- | --- | --- |
| 模型适用范围 | 工程用途、抽象、忽略的效应及前提 | 某次仿真通过不证明模型适用于任意负载、频率或历史 |
| 任务要求满足的范围 | 合法输入、参数、历史与工况组合，以及其中要求的行为或性能 | 三个 PVT 点不自动成为连续包络或全笛卡尔组合；少测几个点也不自动缩小既定范围 |
| 具体验证用例 | 哪些输入、时序和变化用于区分正确实现与典型错误 | checker 没测某种情况不表示该情况被公开排除 |
| 数值测量预算 | 指标算法、采样或积分窗口、离散分辨率、插值和求解误差 | 台架采样间隔不等于允许模型延迟，求解容差不等于可接受模型误差 |

性能目标与模型误差还应分别命名。例如建立时间是电路行为指标，允许输出误差是模型验收界，
时间定位和插值误差属于测量预算。若最大输入斜率为 S、时刻误差预算为 Δt，S·Δt 只估算
这项时间误差造成的幅值误差，不能单凭它决定模型应达到几 mV，也不能证明该精度已可达。
数值目标优先来自应用要求或可信来源；缺少来源时，作者说明所选尺度与用途的关系、备选方案
及影响，再按现有权限作决定。随后用获准的校准检查测量能力，不为适应 checker 而默改目标。

核对完整性时，用同一合法输入和历史，给出两种读法对某个输出是否合格产生的分歧，指出缺少
哪条判定规则。规格可以允许一组输出，无需规定唯一答案。容差内差异、明确允许的随机性和
实现选择都可以合法；内部组织不同而外部行为满足相同约定时，也不增加限制。
拓扑、器件类型或组件职责是否必需，由本题工程工作决定，不能仅由一份 gold 或测试标题决定。
继承既有工程的修复题还须单独明确可修改范围与必须保留的职责。

对高风险旧资产可以先从代码盲重建，再由另一独立会话对照完整公开合同。它能暴露不可恢复的
作者意图、测量缺口和来源冲突，不保证恢复原题，也不替代工程需求。新题没有原题可对照时，
直接依据工程材料和已声明选择审查公开合同。未决项继续留在现有来源记录和阶段状态中，
不新增强制中间格式，不把每个待定字段都变成一轮人工确认。

## 用三个例子讨论题目是否成立

以下是用于讨论的代表方向，没有给出已冻结的数值或已通过校准的声明。

| 方向 | 给定材料与交付物 | 独立验收思路 | 最需要同行判断 |
| --- | --- | --- | --- |
| Alexander BBPD 单模块 | 给出接口、内部三点采样与历史对齐要求，交付完整 VA 判相模块 | 从数据和时钟输入独立重建样本组，检查方向、启动有效性和输出时序 | 理想采样与重合边沿规则怎样定义才合理？允许哪些实现差异？ |
| 真实采样级数据建模 | 给出输入、时钟、前置历史、工况及表征记录，交付同接口 VA 模型 | 用留出的完整实验比较波形、采样误差和公开指标 | 哪些动态确实存在？公开实验是否足以辨识它们？ |
| POR 测试与检查 | 给出可读 DUT、接口和电源复位要求，交付 VA 激励与监测模块 | 独立检查实际施加的条件、测量值、误报、漏报及报告时机 | 哪些电源轨迹与复位性质最重要？延迟应从哪个事件计起？ |

系统任务另有一个必须回答的问题：模块是否真正参与规定的系统行为？例如补齐 SAR ADC
比较器或 SAR 逻辑，应检查指定职责、接口和协作。仅把外部模拟输入直接量化为数字码，
即使最终输出接近，也不能证明完成了要求保留内部架构的系统任务。

## 人工如何判断题目质量

好的题目对应有价值的电路工作，求解者能根据公开材料完成，成绩能够说明目标能力。
两条电路路线共同采用以下标准；功能族讨论先判断内容，合同与完整题包阶段再核实对应材料和证据。

| 审核重点 | 人工需要作出的判断 |
| --- | --- |
| 工程价值 | 说明使用场景、交付物的用途及要解决的问题。通用数学问题附上电路名称不足以成立 |
| 电路行为与抽象 | 指出必要状态、动态与端口作用，说明允许忽略的效应、假设及适用范围。真实现象与教学假设分别提供依据 |
| 工作边界 | 给定材料、求解者决策与交付形成完整的工作单元。主要工作用于目标能力，文件操作与报告负担合理 |
| 材料充分与公平 | 独立工程师只凭公开材料即可理解和完成；没有隐藏要求，允许符合合同的不同算法与实现 |
| 验收有效性 | 观察能够代表工程目标，能区分正确方案、典型错误和绕过目标的做法；独立依据、测量定义与容差理由可信 |
| 相对已有题的贡献 | 明确新增的工程责任或关键行为，保留来源关联；普通参数变化作为测试条件，不重复计题 |

基础题和人工构造题可以保留，但应准确限定它们支持的能力结论。例如允许整体重写的短模块
修复题，可能主要考规格重建，不能只因提供了坏代码就认定它考察了复杂诊断。
参考解通过说明存在可行解；其他合理正确实现能否通过、典型错误能否被检出，仍需校准。

人工审核一套题时，还要判断整体覆盖与结果解释：

- 电路类型、关键机制和工程动作是否支持声称的评测范围，不要求每个功能族凑齐五类。
- 同源题是否增加了不同责任；保留关联，不能把多个变体当作多个独立电路架构。
- 基础题与挑战题是否适合评测目标；难度和区分度由后续试跑检验，环境与交付障碍单独分析。

每个电路组给出保留、修改或合并、证据不足而暂缓的内容结论及理由，并列出待人工取舍。
这些是审核意见，不因 Agent 梳理或校准通过自动成为人工认可；正式录取仍按既有流程执行。

## 上下文、来源与题数分别记录

三个上下文层次均保留：单个工作单元、有边界的小工程、完整仓库任务。
首轮完整仓库任务较少，具体数量在代表题研究后确定。提供多个文件不自动构成系统任务，
要求修改多个文件也不自动形成更高难度。

任务来源允许真实工程问题、合理人工故障和依据明确工程需求原创的任务。
每题标明来源、实际用途、正确行为和验收依据；人工错误还需解释发生机制。
来源与分发遵循[使用约定](../../historyref/README.md#使用约定)。

旧 DUT、Testbench、Bugfix 是候选来源，不要求成套迁移。
普通参数变化作为测试条件，不增加题数；新增工程要求是否构成新任务需单独说明。
报告同时给出任务数、来源分组与工程工作覆盖，最终汇总口径仍待确定。
旧七类各 5–10 题的配额不再是当前建设目标，历史资产和成绩保留原身份。

## 先确认工程价值，再确认难度

保留少量容易但重要的基础任务，核心挑战题需要在合理交互预算下仍有区分度。
一次失败、代码长或参数多都不足以证明困难。
首次提交出错后立即根据反馈修好，可以分析过程，但不能单凭这一点认定为挑战题。

建设顺序是明确工程场景，定义交付物和公开合同，校准参考解及典型错误，
再用多个模型试跑，区分任务缺陷、环境问题和模型能力不足，最后冻结合格版本。
校准与评测细则见[评测原则](evaluation.md)。

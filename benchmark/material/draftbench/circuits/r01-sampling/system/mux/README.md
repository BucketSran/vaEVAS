# 四路输入复用与共享采样级

这个工程用于共享单个采样级的扫描式数据采集。选择器先接通一个输入，采样节点再用有限时间接近该输入。下一通道的初始采集状态来自前一通道留下的电压，因此高低通道交替时，短采集会留下可见历史误差。这是供电路 review 的工程资产，尚未冻结题目合同，不计入正式任务。

`circuit.va` 实例化一个 [公共采样核心](../../module/core/track_hold.va)。四路输入通过顶层选择器接到 `mux_in`，公共核心的输出是 `held`。输出门控直接读取 `held`，没有在顶层另存模拟样本，也没有在切通道时复位。它与四路同步架构的区别是存储节点数量和采集时刻，通道数只是接口宽度。

## 接口与样本归属

输入使用 0.2 至 1.6 V，控制使用 0 与 1.8 V，判定阈值默认为 0.9 V。

| 端口 | 含义 |
| --- | --- |
| `ain0` 至 `ain3` | 四路模拟输入 |
| `sel0`, `sel1` | 下一次采集的二进制通道码，`sel0` 是低位 |
| `track` | 高电平采集，下降沿结束本次采集 |
| `rst` | 高电平优先复位共享保持节点并丢弃当前样本 |
| `read_en` | 高电平允许读出，低电平暂停读出 |
| `dout`, `valid` | 可读时输出当前保持电压，`valid` 为 1.8 V；其他周期两者趋向 0 |
| `owner0`, `owner1` | 本次采集锁存的通道码，`owner0` 是低位；有效样本用这个码解释归属 |
| `held` | 共享保持节点的持续观察输出 |

`track` 上升时锁存选择码，并使旧样本无效。选择器在整个采集窗口使用该码，因此采集期间外部选择码变化不会把两个通道混为一个样本。`track` 下降后，当前样本有效，归属码继续保留。保持期间可以提前设定下一通道，但当前样本不会因此改名。`valid` 表示当前样本可读，不保证完成足够采集或达到某个精度。

仿真开始时若 `track` 高且 `rst` 低，模块在起点锁存选择码并开始首次采集。若复位释放时 `track` 已高，模块在复位释放时锁存选择码并重新采集。两种情况都在之后的 `track` 下降沿才形成有效样本。复位是有限恢复，必须留够时间；任何通道选择和普通采集开始都不触发复位。

台架在采集开始前至少提前 19 ns 建立选择码，复位释放的最后一段采集也先设好选择码。不要让选择码、复位和采集边沿同时变化。读取只在保持阶段有效，默认门控过渡为 1 ns，应等过渡结束后观察。`read_en` 只控制读出，共享保持节点在暂停期间继续漏泄。`owner` 在采集期显示本次目标，在无有效样本的周期不能当作已完成样本标签。

## 运行与观察

从本目录进入对应台架目录后运行 Spectre：

```sh
cd ../../test/mux
spectre tb.scs
```

台架引用公共采样核心与本目录的 `circuit.va`，保存输入、控制、通道码、`held`、`dout`、`valid` 与内部 `Xmux.mux_in`。仿真结束时间为 7 us，没有评分程序或预制测量数据。

输入 0 和 1 分别固定为 0.2 与 1.6 V。首段约 100 ns 采集高通道，接着约 5 ns 采集低通道，再用约 5 ns 回到高通道。约 700 至 800 ns 长采集低通道，900 至 1000 ns 长采集高通道，1100 至 1105 ns 再次短采集低通道。波形可比较同一目标输入下的长短采集，也可检查短采集结果是否依赖前一通道电压。所有这些采集共用同一个存储节点。

2 至 4 us 暂停读出，恢复后仍读同一个样本，但 `held` 已继续漏泄。6 至 6.201 us 复位，`track` 在复位期已拉高，因此从复位释放至约 6.351 us 采集通道 2，检查复位释放时的采集归属与有效输出。各时间是激励边沿名义值，实际开关判定发生在 0.9 V 阈值处。

`tau_acq=10 ns`、`tau_hold=200 us`、`vinit=0.9 V`、`vleak=0 V`、`pedestal=2 mV` 是工程设计取值，公共核心以连续动态演化。短采集与长采集的差异由采集时间和历史状态产生，不是顶层人为添加一个误差常数，也不是器件实测拟合。

## 表征题交付草案

候选名称为“MUX 共享采样的历史状态与采集窗口表征”，属于电路测试与表征，先按基础题设计。它比较在同一目标输入下，前置状态和采集窗口长度分别怎样影响结果，并保留采集误差、保持变化和最终读出误差。定义以[功能族约定](../../reference.md#表征题的测量范围与实际事件)为准。

给定源码可读的完整 MUX 工程、激励端口与连接、两组实验条件表、公开时间和电压范围，以及比较条件的允许差异。求解者交付执行条件表并记录实际事件的 VA 表征模块与报告。可拆成激励和测量两个模块，不以文件数区分题型。题目不要求自动寻找最佳扫描顺序或最佳采集窗口。

实验表规定希望施加的条件；实际记录决定实验是否按要求发生。前置准备不能只写“上一通道为高电平”，必须读取本次目标采集开始时的 `held`。上一轮采集可能未充分建立，等待也会改变这份电压。

### 作者审核用伪代码

伪代码中的调度负责施加规定实验，事件记录负责确认实际过程。不能用计划时刻、计划通道或模型参数替代观测。

```text
执行两组公开条件表：
    历史组：固定目标输入、目标采集窗口和读出等待
            使用不同前置准备，使目标采集的起始电压不同
    窗口组：重复相同前置准备，改变目标采集窗口
            核对实际起始电压仍在公开的可比范围内

对每个实验轮次：
    建立独立轮次记录，注明组别和计划条件
    若需要初始化，在本轮前置准备之前执行
    驱动前置通道的规定采集与保持过程，记录真实事件和响应
    选择目标通道，按公开时序启动目标采集
    前置通道与目标采集之间不复位
    根据实际采集开始事件安排本轮窗口的结束命令
    根据实际采集结束事件安排读请求，保持规定的读出等待
    等待测量完成或公开期限到达；失败时保留本轮部分记录

每次实际采集开始时：
    关闭上一样本及其待完成读取，保留旧记录
    保存新的样本序号和 t_a
    依据此刻的实际 sel 锁存本次路由，不随以后 sel 改变
    保存起始 held、此前通道或复位状态、前置采集与保持历史
    把本样本关联到当前实验轮次的“准备”或“目标”阶段
    核对 DUT owner 时考虑其公开输出过渡，不把它当作唯一来源

实际采集结束时，若存在未被中断的采集且 rst 为低：
    保存 t_h 和实际窗口长度 t_h - t_a
    u_ref = 本次锁存通道在此刻的输入
    h_end = 此刻的 held
    采集误差 = h_end - u_ref
    标明样本已完成采集；使能已高时启动读出观察

形成合法读请求时：
    关联到当前已完成样本，并在公开观察间隔后取样
    若发生新采集、复位或取消，终止该请求，不跨样本拼接
    否则保存实际 t_r、held、dout、valid 和 owner
    保持变化 = held - 本样本 h_end
    最终读出误差 = dout - 本样本 u_ref
    重读追加记录，不改变样本序号、输入参考或前置状态
    状态输出异常单独报告，不以异常状态为由静默跳过观察

比较两条目标采集记录时：
    核对采集窗口内的实际目标输入、模型配置和实际读出等待
    历史组另核对实际采集时长，展示实际起始电压的差别
    窗口组另核对准备过程和实际起始电压，展示实际窗口差别
    若条件可比，报告两条记录及三项指标的差异
    否则保留数据并说明不满足哪项比较条件，不输出归因结论

被中断或仿真结束时：
    关闭被中断的样本及待处理请求，保留各轮已知状态与已完成读数
    未发生的采集结束或读取标为未完成，不填零
```

初始时刻已经采集、复位释放时已经采集，也按实际开始事件记录。前置通道身份由此前记录保存，不能在目标开始后从已更新的 `owner` 倒推。实验计划和本轮路由不一致时，应记录差异，而非把计划标签附到实际读数上。

本工程已锁存当前路由，采集或读出期间的外部 `sel` 改变可以是在准备下一通道。测量模块不因此重新命名当前样本或取消读取；这与同步系统由 `sel` 直接选择读出节点的规则不同。

历史比较中的起始电压差是要观察的因素。窗口比较中的起始电压差则可能破坏可比性。例如，两个实验都写着“先采高通道”，但目标开始时分别为 1.55 V 和 1.20 V，就不能直接把目标采集误差差异归因于窗口长度。可比范围须公开，具体数值在题面细化时确定。

### 与相近题目的区别和材料缺口

同步表征跟踪同一帧的多个独立保持节点，主要观察采集和等待读出；本题组织前置准备与目标采集，共享一个节点，并判断比较条件。它复用 core 的历史状态与有限采集机制，实验组织是新增工程工作。两组条件是同一交付物的职责，不因增加条件数量而增加题数。

现有台架已有高低通道切换和长短窗口，但它不是完整的两组受控实验包。还需补条件表、比较范围、VA 表征模块与报告接口。完整连续扫描可以后续增加，不作为本基础题的隐含责任。本文未实现参考解、checker 或模型实验。

提前选通扩展与中断恢复修复共享本系统。扩展从健康旧协议工程出发，修复从违反已有协议的故障工程出发。简单标签改动仅作基础候选，不替代原来的中断恢复方向；两种修复所需故障与复现材料均需另补。

## 来源、范围与后续工程工作

[TI TIPD169](https://www.ti.com/tool/TIPD169) 是多路复用数据采集参考设计，讨论输入切换后的建立时间与采样吞吐率。[ADI MT-090](https://www.analog.com/media/en/training-seminars/tutorials/MT-090.pdf) 说明采样保持在采集、转入保持和保持阶段的误差。本工程依照这些机制选择电压域架构，没有复制参考设计的器件模型或把其测量指标移植为本模型参数。

本资产没有模拟输入驱动器极点、物理 mux 导通电阻、切换电荷注入、ADC 量化或数字输出协议。路由是理想选择，有限建立与残留由共享采样核心提供；实际系统的输入驱动器与 ADC 采样电容可能需要多个动态状态。本资产能用于比较扫描顺序、采集预算和历史误差，不能代表 TIPD169 的器件性能。

后续可以围绕相邻通道的大电压步进规划扫描顺序，为每通道分配不同采集窗口，或加入输入驱动器动态并分析吞吐率与误差约束。形成正式工程任务时，还需要独立判据与实际验证，本阶段不生成 checker、Harbor 任务或模型解题实验。

后续扩展统一见[暂缓候选与优先级](../../reference.md#暂缓候选与后续优先级)。本轮不建设这些候选。

# IR-UWB TX 种子链：系统行为约定

本页规定 8DPPM+8FSK、4.032 Gb/s 种子发射链的 Verilog-A 交付范围、模块职责、接口和验收。
需求来源是用户提供的工程 SPEC《IR-UWB TX 调制与低功耗架构筛选 SPEC V1.0》（2026-10-22，下称“原 SPEC”），
本页只覆盖其中由 Verilog-A 负责的部分（原 SPEC §11），不含 MATLAB 频谱、信道、BER 与距离计算。
任务记录见 [#223](https://github.com/BucketSran/vaEVAS/issues/223)。

每条行为都标明依据：**来源** 指原 SPEC 或论文明确给出；**选择** 指本项目为补齐 SPEC 而定的建模选择，可以替换；
**待定** 指尚未决定，实现中只保留接口或测试条件。

## 1. 范围

第一里程碑交付种子链 M1–M4，第二里程碑 M5 加入原 SPEC §7.2、§8、§12.2 中现在就能做的部分：

| 里程碑 | 内容 | 原 SPEC |
| --- | --- | --- |
| M1 数据与编码 | 测试数据源、6 bit 串并转换、DPPM+FSK 编码器 | T1，§6.3 |
| M2 时钟与校准 | 672 MHz 16 相主 RO、48 MHz 参考比 14 的频率校准 | T2，§6.3–6.4 |
| M3 脉冲与单支路 | 脉冲发生器（PG）、单个 RF 支路 RO 的预充电、释放、起振 | T3，§7.2 |
| M4 整链 | 8 支路调度器、包络通道、合路、PA、差分输出 | §6.1，§7.3 |
| M5 预热、非理想与导出 | 释放提前量（预热）、§8 中可以直接建模的误差、支路隔离、事件导出与参数化功耗记账 | §7.2，§7.4，§8，§12.2 |

M5 的全部新参数默认关闭，关闭时行为与 M4 相同（见 4.10）。仍不在本交付内：

- PA 压缩与 AM-PM：原 SPEC §8 要求不能把无记忆幅相公式直接套在实数 RF 电压上，需要先定复包络或因果包络估计的建模方式，**待定**。
- 供电纹波、RO 互耦、输出阻抗与带宽、延迟漂移、占空误差：需要提参数据或超出电压域行为模型。
- 外部 4.032 GHz 数据时钟与自由运行 RO 之间的 CDC：**待定**，用户要求保留三种方案（同源晶振+FIFO+限包长、RO 域反压、数据时钟由 TX 提供）以后讨论。
- 其他 RO 架构（预置 loop、单可调 RO、分组 RO 等，原 SPEC §7.1）：关键差异依赖晶体管数据，等需求方选定候选。
- PWM/PAM/PSK 等其他调制（M6）；供电电流波形（电压域模型不产生真实电流，功耗按 4.10 的事件记账）。

## 3. 架构

```text
bit 源 ─▶ 串并(6) ─▶ 编码器 ─▶ PG ─(2 条命令通道)─▶ 调度器 ─▶ 8 个 RF 支路 RO
                                ▲                         │            │
48 MHz 参考 ─▶ 频率校准 ─▶ 16 相主 RO ─(16 个抽头)──────────┘            │
                                │                                      ▼
                                └──────────▶ 2 个包络通道 ─▶ 合路/DPC/PA ─▶ outp/outn
```

模块边界沿用原 SPEC §6.2 的职责划分，补充两条选择：

- **δ₀ 格点来自主 RO 的 16 个相位**（选择，用户确认）。主 RO 是 8 级差分环，16 个抽头依次相差 Ts/16 = δ₀。
  校准 RO 频率即同时校准全部抽头，与 Lei 等 JSSC 2024 的做法相同（其式 (1) 也给出了位置递推
  `PPC_i ≡ D16PPM_i + PPC_{i−1} (mod 16)`）。
- **PG 用两条交替的命令通道**（选择）。偶数符号走通道 a，奇数符号走通道 b。相邻符号若用同一载频且首尾相接
  （位置 7 之后接位置 0），两个 RF 窗口在同一抽头边沿交接；分在两条通道上，下游才能看见第二个脉冲的开始。

## 4. 模块行为

### 4.1 测试数据（测试设施，不是被测电路）

bit 流由 checker 用 Python 生成，作为分段线性电压源送入；bit 时钟和 48 MHz 参考由
[test/sources/clock_source.va](test/sources/clock_source.va) 产生。覆盖序列按原 SPEC §10.1 的要求，
先生成绝对码字 (P, F) 的 de Bruijn 序列（k=64、n=2，按 Lyndon 词拼接，末尾补回第一个码字，共 4097 个），
再按差分映射 D = (P[n] − P[n−1]) mod 8 和 Gray 编码反推出输入 bit。原 SPEC 中的 bitStream 由用户提供，不在本交付内。

### 4.2 6 bit 串并转换（`uwb_serial_to_symbol6`）

| 行为 | 依据 |
| --- | --- |
| 在 bclk 上升沿采样 din；复位释放后第 1 个采到的 bit 进入 symbol<5>（先到先高位） | 选择 |
| 第 6 个 bit 采到时，6 位同时更新到输出，symbol_valid 置高；输出保持到下一个符号更新 | 来源：原 SPEC §6.2“6bit 保持” |
| symbol_valid 高 3 个 bit 周期，在下一符号第 3 个 bit 采样沿拉低；下降沿处输出已稳定 | 选择，配合编码器“下降沿收字” |
| rst 高电平异步复位：计数清零，输出和 symbol_valid 为 0 | 来源 |
| 输出相对采样沿延迟 t_cq（默认 10 ps） | 选择 |

### 4.3 8DPPM+8FSK 编码器（`uwb_dppm_fsk_encoder8`）

| 行为 | 依据 |
| --- | --- |
| 在 symbol_valid 下降沿收字 | 来源：原 SPEC §6.3 |
| D = gray2bin(symbol<5:3>)，F = gray2bin(symbol<2:0>)；gray2bin：b2=g2，b1=g2⊕g1，b0=g2⊕g1⊕g0 | 来源（反 Gray） |
| P[n] = (P[n−1] + D[n]) mod 8，P[−1] = 0；复位后第一个字的 P = D | 来源 |
| 输出 position_code = P（绝对位置）、dppm_increment = D（调试量）、frequency_code = F、ro_request 独热（第 F 位为高） | 来源 |
| 数据在收字后 t_enc（默认 10 ps）更新；encoded_valid 在收字后 t_ev（默认 30 ps）上升，高 t_pw（默认 400 ps） | 选择；来源要求“上升沿供后级锁存”，重复相同字也必须产生新上升沿 |
| ro_request 只表示选频请求，不是 RO 电源、预充电或 RF 使能 | 来源 |
| rst 高：P 清零，输出为 0 | 来源 |

### 4.4 16 相主 RO（`uwb_master_ro16`）

| 行为 | 依据 |
| --- | --- |
| f = f0 + code × fstep，f0 = 600 MHz，fstep = 0.25 MHz | 来源 |
| 16 个抽头 ph0…ph15，占空比 50%，抽头 k 比 ph0 晚 k·δ（δ = 1/(16f)） | 选择（8 级差分环） |
| 调谐码变化时相位连续：保留当前抽头间隔已走过的比例，按新频率走完剩余部分；不重置相位 | 来源：原 SPEC §6.4“不允许理想重置 RO 相位” |
| 初相可设（phase0，周期分数），默认 0 | 选择 |
| 常开，不受数据控制 | 选择；原 SPEC 中公共时序 RO 不计入支路供电数 |
| 码位跳变后延迟 t_code（默认 5 ps）读码，多位同时变化只读一次；t = t_code 时再读一次，防止初始时刻码尚未有效 | 选择 |

### 4.5 RO 频率校准（`uwb_ro_frequency_cal`）

| 行为 | 依据 |
| --- | --- |
| cal_start 上升沿开始校准：busy=1，done=fail=0 | 选择 |
| 10 位逐次逼近，从最高位开始：试置该位，等待 n_settle 个参考周期（默认 2），再在 n_win 个参考周期（默认 192）内数 RO 上升沿；计数大于目标 n_win × 14 则清该位，否则保留 | 选择；来源只说“48MHz 参考比 14、测量搜索” |
| n_win = 192 时，计数 = 2400 + code，1 个码对应 1 个计数；只数 1 个参考周期分不出 0.25 MHz 步进 | 推出 |
| 10 步后用最终码再测一次：|计数 − 目标| ≤ tol（默认 1）则 done=1，否则 fail=1；busy=0 | 选择 |
| done 或 fail 后码冻结，直到下一次 cal_start；done 只表示频率达标，不表示相位同步 | 来源 |
| 参考缺失：最后一个参考上升沿之后，第 n_lost+1 个（默认第 65 个）RO 上升沿到来时仍无参考沿即 fail；fail 时输出已经保留的码（不输出未测完的试探码） | 选择；原 SPEC §10.1 要求测参考缺失 |
| 计数窗口：cal_start 之后第 n_settle 个参考上升沿开窗，再过 n_win 个参考上升沿关窗；窗内严格位于两沿之间的 RO 上升沿计数 | 选择 |
| 码、done、fail、busy 在决定它们的参考沿（或 RO 沿）之后 t_cq（默认 10 ps）更新 | 选择 |
| 复位或上电后、校准前输出 code_init（默认 512） | 选择 |

一次完整校准约 11 × 194 个参考周期 ≈ 44.5 µs。校准过程不承载数据（原 SPEC §6.4）。

### 4.6 脉冲发生器 PG（`uwb_pulse_generator`）

| 行为 | 依据 |
| --- | --- |
| encoded_valid 上升沿锁存描述符 (P, F, pol) 到待发寄存器 | 来源：原 SPEC §6.3、§6.5 |
| 帧边界是 ph0 上升沿。帧 k 开始时把待发描述符排进帧 k+1（预留一个符号准备时间） | 来源：“预留一 symbol 准备时间”；帧对齐方式为选择 |
| en（如校准 done）只在 ph0 上升沿采样；使能后从完整帧开始，不把 done 与原始时钟相与 | 来源：原 SPEC §6.4 |
| 设帧 k+1 的起点抽头序号为 A：脉冲开始于抽头 A+P 的上升沿，结束于抽头 A+P+9 的上升沿（可跨入下一帧），宽度恰为 9δ | 来源（Tp=9δ₀、Δ=δ₀）；用抽头边沿实现为选择 |
| 预充电命令从抽头 A+P−n_pre 开始，到脉冲开始结束（n_pre 默认 2，即约 186 ps）；可能落在帧 k 内 | 选择：原 SPEC §7.2 只给出公式，没有 T_precharge 数值 |
| 输出到当前符号所属通道：pre_x、rf_x、sel_x<2:0>、pol_x（x = a 或 b）；按**已排程**的符号交替，被覆盖而未发出的字不占通道 | 选择 |
| sel_x、pol_x 在排程时（帧边界）改变，此后保持到该通道下一次排程；调度器在 pre_x 上升沿读 sel_x，输出级在 gate_x 上升沿读 sel_x 和 pol_x | 选择 |
| pol 脚与 (P, F) 一起在 enc_valid 上升沿锁存，外部极性源须在此之前稳定；编码器不产生极性 | 选择 |
| enc_valid 与 ph0 上升沿同刻时，先锁存再排程 | 选择（实现中事件顺序，待 Spectre 确认） |
| rst 上升：清空待发字和两个通道的预充电/RF 窗口，通道交替回到 a；sel_x、pol_x 和正在进行的 overrun 脉冲保持 | 选择（按 gold 行为写明，2026-10-23 题包建设时发现原文含糊） |
| n_width ≤ 9：P + n_width > 16 时同一通道下一次排程会落在窗口进行中，gold 不处理这种重叠，所以合法范围是 1–9 | 选择（M5 起 gold 参数声明也改为 1–9） |
| 某帧没有新描述符时不发脉冲；待发描述符未被取走又被覆盖时输出 overrun 脉冲（宽 t_ovr，默认 200 ps）；en 低期间待发字不被取走，所以每个新字都会报 overrun，en 恢复后发出最后一个字 | 选择 |

T_launch_lead 取 0（原 SPEC §7.2“首版检查 T_launch_lead=0”），所以释放时刻等于 RF 命令开始时刻，PG 不另出释放命令。

### 4.7 8 支路调度器（`uwb_ro_scheduler8`）

每个支路维护状态 OFF、PRECHARGE、RELEASE_SETTLE、ACTIVE、TAIL、HOLD（来源：原 SPEC §7.3）。
除 OFF 外都算供电，同时供电的支路不超过 2 个（来源）。T_launch_lead=0 时 RELEASE_SETTLE 时长为 0。
实现上调度器持有 2 个供电槽，支路只有占到槽时才上电（选择；并发数改变属于新结构，原 SPEC §7.3）。
冷启动总要先预充电，所以调度器要求 n_pre ≥ 1。

| 事件 | 处理 | 依据 |
| --- | --- | --- |
| 通道 x 的 pre_x 上升（请求支路 k = sel_x） | 支路 k 正在 PRECHARGE/ACTIVE/TAIL/HOLD：不另占供电，记为“热请求”，继续振荡（或继续预充电）；否则若供电数 < 2：k 进入 PRECHARGE；否则若有一个支路处于“无待发请求的 HOLD”：先关掉它再让 k 预充电；否则丢弃该符号（不发 RF），输出 conflict 脉冲 | 前两条来源；丢弃策略为选择（用户未改动建议）；抢占空闲 HOLD 为选择 |
| rf_x 上升且该请求已获准 | k 进入 ACTIVE；从 PRECHARGE 进入时在此刻释放（冷启动），从 HOLD/TAIL 进入时相位连续；通道门控 gate_x 置高 | 来源：§7.2、§7.3 |
| rf_x 下降 | gate_x 拉低；k 进入 TAIL，时长 t_tail（默认 150 ps）；若另一通道此刻接着在 k 上开始，k 保持 ACTIVE | t_tail 来源：§8，50 ps 99% 建立在 10⁻⁶ 门限下约 150 ps |
| TAIL 结束 | 有热请求：进入 HOLD 等它开始；否则进入 HOLD 并等待 max(0, t_hold − T_pre)：期间来了 k 的请求即转为热请求，否则 OFF | t_hold = 200 ps 来源；T_pre = n_pre·δ₀；合起来见下方“保持条件” |
| 任何状态 | 正在 ACTIVE/TAIL 的支路不被下一字覆盖；OFF 后不产生载波 | 来源 |

**保持条件。** 请求在下一脉冲开始前 T_pre 到达，所以上面几条合起来是：下一脉冲开始距尾部结束的间隔 g ≤ max(t_hold, T_pre) 时保持振荡，否则关断再冷启动。
T_pre ≤ t_hold（默认 n_pre=2，T_pre=186 ps）时就是原 SPEC 的“200 ps 内保持”。T_pre > t_hold 时，g 落在 (t_hold, T_pre) 内的冷启动来不及预充电，
所以继续保持（选择；原 SPEC §7.3 的 200 ps 门限没有覆盖这种情况）。
请求恰好落在空闲 HOLD 结束的同一时刻时按热请求处理。
两个支路同时处于无待发请求的 HOLD 时，新请求接管哪一个，本约定没有规定（gold 取内部第一个供电槽，外部看不出依据）；题目把这种情形排除在合法输入之外，是否改为“接管空闲最久的支路”待定。

输出：每支路 pwr_k、pre_k、rel_k，每通道 gate_x，conflict 脉冲（宽 t_conf，默认 200 ps），供电数 nsup（每个支路 1 V），以及每支路状态监测电压（0.2 V × 状态号）。
rst 上升时全部支路 OFF，两个通道清空。

按种子时序推出：同时需要 3 路供电当且仅当 n_pre + t_tail/δ₀ > 16（推导见[附录](#附录第三路供电的条件)）。默认参数（2 + 1.6）不会触发，
冲突测试用加大的 n_pre 强制触发。

### 4.8 RF 支路 RO（`uwb_rf_ro_branch`）

| 行为 | 依据 |
| --- | --- |
| pwr 低：输出 0；PRECHARGE（pre 高、rel 低）：节点预置，不振荡，输出 0 | 来源：§7.2 |
| rel 上升（释放）：幅度 a(u) = 1 − exp(−u/τ_a)，频率 f(u) = f_k(1 + ε·exp(−u/τ_f))，u 为释放后的时间 | 来源：§8 种子“幅度/频率 99% 建立各 200 ps”（τ = 200 ps/ln100 = 43.4 ps）、“启振额外频差约 1%”（ε 默认 +0.01） |
| 相位按支路局部时间累积：φ(u) = φ₀ + 2π f_k [u + ε τ_f (1 − e^{−u/τ_f})]；HOLD 和连续脉冲期间相位连续，不在符号边界重置 | 来源：§5.4 要求写明局部相位；φ₀（预置相位）为选择，默认 0 |
| 输出 vro = A_ro · a(u) · cos φ(u)，A_ro 默认 1 V | 选择 |

### 4.9 包络通道、合路与输出（`uwb_envelope_lane`、`uwb_tx_output`）

| 行为 | 依据 |
| --- | --- |
| gate_x 上升时开始一个全升余弦包络 e_cmd(u) = ½(1 − cos(2πu/T_w))，T_w = 9 × 实测 RO 周期 / 16 | 来源：§5.1“全升余弦为种子”；T_w 取实测周期为选择 |
| 包络经一阶有限响应 τ_e = 50 ps/ln100 = 10.9 ps，用闭式解实现；窗口结束后按指数衰减，形成受控尾部 | 来源：§8“PA/DPC 幅度链路 99% 建立 50 ps” |
| 合路：v = G_pa · Σ_x (−1)^pol_x · g_dpc[sel_x] · env_x · vro[sel_x]；sel_x、pol_x 在 gate_x 上升沿锁存，通道被重新排程时不改变正在衰减的尾部；通道未获准时 env_x = 0 | 选择（两条包络通道是对 DPA 的行为抽象） |
| 差分输出 outp = V_cm + v/2，outn = V_cm − v/2；测量电压为 outp − outn | 来源：§2.2 |
| DPC 增益 g_dpc[k] 默认 0 dB（参数），PA 为线性增益 G_pa | 选择；压缩/AMPM 待定建模方式（见 4.10） |

### 4.10 M5：预热、非理想与导出

所有参数默认关闭；关闭时各模块走与 M4 相同的路径，M1–M4 的检查在 M5 版本上重跑全部通过。

**预热（释放提前量，原 SPEC §7.2）**

| 行为 | 依据 |
| --- | --- |
| PG 参数 n_lead（抽头数，0–15，n_pre + n_lead ≤ 15）。释放命令在 r = s − n_lead，预充电从 p = r − n_pre 开始；pre_x 在 p 升、在 r 降，rf_x 仍在 s 升、e 降 | 来源：§7.2 t_release = t_RF − T_launch_lead；以抽头计为选择，n_lead = 0/1/2/5/11 约对应 §8 的 0/100/200/500/1000 ps |
| 调度器在 pre_x 下降沿释放仍在预充电的支路，进入 RELEASE_SETTLE（振荡、rel 高、门控低）；rf_x 上升时进入 ACTIVE。n_lead = 0 时两者同刻，RELEASE_SETTLE 长度为 0 | 来源：§7.3 状态表 |
| 保持条件按“下一次释放”计：请求在释放前 n_pre·δ₀ 到达，空闲 HOLD 仍等 max(0, t_hold − n_pre·δ₀) | 选择（与 4.7 一致） |
| 预热期间支路在振荡，计入供电时间和能量 | 来源：§7.1“提前预热本身也耗能” |

**PG 定时误差（原 SPEC §8：符号抖动 5 ps，位置/宽度额外误差各 2 ps）**

| 行为 | 依据 |
| --- | --- |
| 每个排程的符号抽一次：j ~ N(0, σ_jit)（该符号所有边沿），ep ~ N(0, σ_pos)（RF 窗口两沿），ew ~ N(0, σ_wid)（RF 窗口结束沿），各截断在 ±clip_n·σ（默认 4） | 来源：§8 数值；按符号抽样来源于 §8“按器件固定、激活、symbol 或物理时间网格抽样” |
| 有误差时每个通道边沿比抽头晚 t_lat_eff = max(t_lat, clip_n(σ_jit+σ_pos+σ_wid)) 再加抽样值，保证负的抽样也是因果的；公共延迟对所有符号相同 | 选择 |
| 宽度误差只作用在 RF 窗口上：窗口变短时包络被提前截断，变长时升余弦形状不变 | 选择（包络长度取实测时钟，见 4.9） |

**主 RO 抽头静态偏斜（原 SPEC §8“公共时钟与 PG：相位 INL/DNL”）**：每个抽头一个固定偏斜 sk_k ~ N(0, σ_tap)，截断 ±clip_n·σ，器件生成时抽一次；所有抽头另加公共延迟 max(tap_lat, clip_n·σ_tap)。占空、延迟漂移未建模。

**RF 支路（原 SPEC §8）**

| 行为 | 依据 |
| --- | --- |
| f_dev = f_k + f_off + f_res：f_off 为共同静态频偏（主档 +25 MHz）；f_res ~ N(0, σ_f_res)（主档 10 MHz）每个器件抽一次 | 来源：§8 |
| a_dev = A_ro·10^(g_res/20)，g_res ~ N(0, σ_g_res)（主档 0.5 dB），每个器件抽一次；与 DPC 分开 | 来源：§8 |
| 每次冷启动（激活）抽 df_act ~ N(0, σ_f_act)（主档 5 MHz），本次激活内固定；保持（HOLD、热请求）不重新抽 | 来源：§8“激活内固定，保持与重新激活状态相关” |
| 冷启动相位：phi_random = 1 时每次激活取 U(0, 2π)，否则为预置 φ₀ | 来源：§8“独立 RO 均匀未知种子” |
| 相位扩散：在固定时间网格 k·t_pn_grid（默认 50 ps）上，每格相位线性变化 N(0, σ_pn·√(t_grid/1 ns))（主档 σ_pn = 5°/1 ns）；释放时从 0 开始，第一格从释放后的第一个网格点开始 | 来源：§8“1 ns 累计 σ5°，固定物理噪声网格”；线性插值为选择 |
| 每个实例用自己的种子（器件、激活、相位噪声三条随机流分开）；系统顶层给支路 k 的种子为 seed_br + 7k | 选择 |
| 支路在 rel 或 pwr 下降时立即停振（与 M4 相同）。打开隔离泄漏时，这一停振会以 1 % 量级出现在输出上 | 选择；是否加关断衰减待定 |

**支路隔离（原 SPEC §8：40 dB）**：输出级参数 iso_db（默认 200，即关闭）。通道 x 的开关在 gate_x 为高时闭合并连接 sel_x；其余正在振荡的支路（包括通道自己的支路在门控降低以后）以 10^(−iso_db/20) 漏到输出。只对实际振荡的支路产生泄漏，与原 SPEC 一致。

**导出（原 SPEC §12.2）**：各模块参数 export = 1 时用 `$strobe` 输出记录。旧 EVAS 0.8.7 在 initial_step 里不输出 `$strobe`，所以器件参数随第一次事件一起报告。

| 记录 | 内容 |
| --- | --- |
| SYM | 编码器收字：时刻、序号、原始 Gray 字、D、P、F |
| PGS | 排程：时刻、序号、通道、P、F、极性、起止和预充电的抽头偏移、j、ep、ew、公共延迟 |
| SCH | 调度器每次事件后的状态：两个供电槽的支路和状态、两个门控、conflict、两个通道占用的槽 |
| ACT | 支路每次冷启动：释放时刻、支路、激活序号、f_act、a_dev、φ_act、f_dev、g_res |
| PN | 相位噪声网格点：时刻、支路、激活序号、当前相位噪声、下一格增量 |
| CAL | 校准结果：时刻、done、码、最后计数（参考缺失为 −1） |
| TAP | 主 RO 抽头偏斜：公共延迟和 16 个偏斜 |

`tools/uwb_export.py` 把 Spectre 日志或 EVAS 的 strobe.txt 转成 CSV 和 manifest，并按原 SPEC §7.4 做参数化功耗记账：各状态时间、冷启动次数、每 bit 启动次数、平均/峰值供电支路数、预充电和保持占比；
当 `tools/power_params.json` 中的所有功率和能量参数都给出数值时，再算各项能量、P_DC 和每 bit 能量。模板中这些参数为 null，表示待提参，脚本只报告时间和次数（原 SPEC §7.4“不填任意小数以制造低功耗”）。

## 5. 测试条件

- **CDC 测试条件**（待定项的临时做法）：链路测试中 bit 时钟取理想 4.032 GHz，主 RO 码固定为 288（恰为 672 MHz），
  两者频率相等、相位差由测试台固定。这只是测试条件，不代表 CDC 方案；FIFO 溢出/欠载要等 CDC 方案确定后再测。
- 校准单独测试（M2），链路测试直接使用已校准码，避免每次先跑 44.5 µs 校准。
- 仿真器：目前用旧 EVAS 0.8.7，Spectre 环境就绪后补跑（见下文“仿真器边界”）。测试台用边沿记录仪（`$strobe`）记录实际节点的过阈时刻，checker 从这些记录和波形独立重算期望。

## 6. 验收

每个模块配独立 checker：从测试激励出发，按本页规则独立计算期望，再与仿真中的实际边沿、事件和波形比较，不复用 gold 代码。

| 模块 | 必测场景（对应原 SPEC §10.1） | 判据 |
| --- | --- | --- |
| 串并 | 复位释放、连续 PRBS、相同符号重复 | 每个 word 的 6 位与输入一致；symbol_valid 次数与时刻 |
| 编码器 | 64 码字 / 4096 相邻对全覆盖、复位后重新开始、相同字重复 | P/D/F/独热逐字一致；每字一个 encoded_valid 上升沿 |
| 主 RO | 固定码、码跳变 | 周期 = 1/f(code)，抽头间隔 = δ；码跳变处相位连续 |
| 校准 | 正常收敛、参考缺失、RO 过快（码清到 0）、RO 过慢（码打满 1023）、done 后再次 cal_start | 最终码对应计数与目标差 ≤ 1；done/fail 时刻与码冻结 |
| PG | 位置最大→最小、最小→最大、同频首尾相接、en 在帧中间到来、n_pre = 0 / 15 | 每个脉冲的开始/结束抽头与宽度 9δ；预充电提前 n_pre·δ；通道交替；overrun |
| 调度器 | 同频重复、A→B→A、全频循环、第三路请求（加大 n_pre）、空闲 HOLD 窗口内的请求（n_pre = 1）、抢占空闲 HOLD（加大 t_hold）、en 关闭 12 帧后再启动 | 状态序列；供电数 ≤ 2；丢弃时无门控且 conflict 拉高；保持条件 |
| RF 支路与输出 | 冷启动、保持、关断、极性、DPC 增益 | 首边沿、幅度/频率建立、相位连续、关断后无载波；outp − outn 与独立重建一致 |
| 系统顶层 | 上电 → 校准 → 发送 | 从 outp − outn 解出的符号与发送一致 |
| M5 预热 | n_lead = 5 | 通道边沿 = 抽头 + 延迟 + 抽样；调度器在 pre 下降沿释放（RELEASE_SETTLE）；窗口开始时幅度已建立 |
| M5 非理想 | 共同频偏与器件残差、激活频偏与随机相位、相位扩散、PG 定时误差、抽头偏斜、隔离 | 用导出的抽样值独立重建 outp − outn（误差 ≤ 2 mV）；抽样统计（均值、标准差、Rayleigh 检验）在 99.9 % 界内；器件值固定、激活值每次冷启动一次 |
| M5 导出 | 导出 → CSV → 功耗记账 | 符号、支路状态与监测边沿一致；状态时间与独立重放一致；参数为 null 时不给能量 |
| M5 联合 | 原 SPEC §8 主档全部打开，n_lead = 2 | 重建一致；接收式解码（能量质心定时 + 过零测频）150/150 正确 |

checker 另用典型错误版本校准：每个错误版本只改一处，必须被对应场景判失败（`test/mutants.py`）。

尚未覆盖：包络窗口提前或推迟结束、RO 周期在脉冲中变化、PG 的 en 中途关闭、校准中途复位、PG/调度器的复位路径、
原 SPEC §10.2 的步长减半收敛检查、§10.1 的“不同包长和间隔”（需 CDC 方案）。“预热不足”已由 M5 的 n_lead 覆盖：n_lead = 0 时窗口开始时幅度为 0，n_lead = 5 时已建立。

### 仿真器边界

2026-10-22 用当前 main 的 EVAS（kernel 0.24.1）试跑：只有用 timer 写的 16 相主 RO 能运行。
多位寄存器同时翻转、整数移位、idtmod 或数学函数中的状态量、大参数 sin、跨模块波形乘积等写法都被拒绝，
缺口记录在 [#229](https://github.com/BucketSran/vaEVAS/issues/229)。全部模块仍按标准 Verilog-A 编写，
目前用旧 EVAS 0.8.7（vaBench r53 认证时的版本）验证；Spectre 环境就绪后补跑。

## 附录：第三路供电的条件

支路为起点 s 的脉冲供电的区间是 [s − n_pre·δ, s + 9δ + t_tail]。相邻起点间隔为 16δ + (P[n] − P[n−1])δ，
连续两个间隔之和为 32δ + (P[n+1] − P[n−1])δ ≥ 25δ。第 1 个与第 3 个脉冲的供电区间重叠，
当且仅当 25δ < (n_pre + 9)δ + t_tail，即 n_pre + t_tail/δ > 16。同一支路的 HOLD 只延长该支路自身的占用（空闲 HOLD 最多再多 max(0, t_hold − T_pre)），
不增加支路数；是否超过 2 路仍以仿真中的实际供电数为准。

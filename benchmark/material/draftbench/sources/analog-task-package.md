## 对 VA starter 的建议与采用

2026-10-14 用户确认采用“默认最小 starter，特殊接口才注释”。本项目的维护规范见[单文件题包](../docs/task-package.md#单文件题的目标规范)；这是本项目的决定，不是 analogbench 的统一强制规则。

来源不支持“每个参数、每个端口都必须写解释性注释”的普遍要求。本页早期建议在 starter 中提供参数声明；2026-10-19 人工 review 已调整本项目规则，新建模型的参数要求写入 Spec，由求解者实现。当前分工以[题包规范](../docs/task-package.md#单文件题的目标规范)为唯一来源；这里保留的外部源码观察不因此改变。

starter 的充分性应以“读题面和公开文件后，能确定对外接口并开始实现”为准，不能只看注释数量。已填代码的修复题可以另保留解释已有实现的注释；完整器件起点与空骨架是不同题型。

本次计数口径：从该 commit 的递归 Git tree 选取以 `tasks/` 开头、以 `/environment/starter/circuit.spi` 结尾的路径，得到 50 个；逐文件读取正文。没有器件实现的 49 个仍都有注释，不能简称为“49 个无注释文件”。

## NMOS LDO 的报告行与真正判定条件

补读 [NMOS-pass LDO instruction](https://github.com/Arcadia-1/analog-design-bench/blob/972f7cd7c95381134387b250edf18f3bd23bdd25/tasks/sky130-nmos-pass-ldo-0p4v-pvt-mc/instruction.md)、[verify.py](https://github.com/Arcadia-1/analog-design-bench/blob/972f7cd7c95381134387b250edf18f3bd23bdd25/tasks/sky130-nmos-pass-ldo-0p4v-pvt-mc/tests/verify.py)、[utils.py](https://github.com/Arcadia-1/analog-design-bench/blob/972f7cd7c95381134387b250edf18f3bd23bdd25/tasks/sky130-nmos-pass-ldo-0p4v-pvt-mc/tests/utils.py)、[tb_point.spi](https://github.com/Arcadia-1/analog-design-bench/blob/972f7cd7c95381134387b250edf18f3bd23bdd25/tasks/sky130-nmos-pass-ldo-0p4v-pvt-mc/tests/benches/tb_point.spi)、[tb_mc.spi](https://github.com/Arcadia-1/analog-design-bench/blob/972f7cd7c95381134387b250edf18f3bd23bdd25/tasks/sky130-nmos-pass-ldo-0p4v-pvt-mc/tests/benches/tb_mc.spi)和[reference.json](https://github.com/Arcadia-1/analog-design-bench/blob/972f7cd7c95381134387b250edf18f3bd23bdd25/tasks/sky130-nmos-pass-ldo-0p4v-pvt-mc/results/reference.json)。下面 Value 是来源的已发布数值，本次没有重跑。七行扁平 `metrics` 不是七项完整合同，真实 checks 包含更多条件。

| source check | bench/测量来源与 checker 的完整条件 | reference 显示与缺口 |
|---|---|---|
| complete_signoff | checker 生成 3 corners × 3 supplies × 3 temperatures × 2 loads = 54 点；每点必须有全部有限必需指标及非空 active-MOS headroom；另要 50 seed，每 seed 都有两负载输出。 | flat Value 54 只显示 PVT/load 数；check message 同时记录 MC=50/50。 |
| pvt_output_range | `tb_point` 的 op 得 vout；54 点最小值 ≥0.35 V 且最大值 ≤0.45 V。 | flat 只显示 minimum=0.399 V；check 同时给 maximum=0.403 V。 |
| quiescent_current | op 得 −I(VDD)，减 ILOAD 与 40 µA；54 点最小 Iq ≥0、最大 Iq <400 µA。 | flat 只显示 maximum=381.082 µA；check 另给 minimum=316.330 µA。 |
| loop_stability | loop series source 注入 AC 1 V，用 −V(loop_out)/V(pass_gate)；第一次下降 0 dB 交点取 PM，第一次下降 −180° 交点取 GM；54 点 PM>45° 且 GM>6 dB。 | flat 只显示 PM=87.348°；check 另给 GM=42.688 dB。 |
| psrr_1khz | 同一 point deck 先关闭 loop AC 注入、开启 supply AC=1，取 −20log10\|VOUT\| 在1 kHz；54 点最差 PSRR>40 dB。 | flat 49.711 dB 与这个单一约束一致。 |
| active_device_headroom | op 的 `show all` 文本解析各 MOS 的 vds/vdsat/id，对 \|id\|≥1 nA 取 \|VDS\|−\|VDSAT\|；跨点取最小值，必须 >30 mV，并要求 point 完整。 | flat 162.785 mV。实现只要求每点解析出的 margin 非空；不另核对预期 MOS 总数，不完整的属性表会被跳过。 |
| mismatch_3sigma_output | `tb_mc` 在 tt_mm/1.8 V/27 C、seed 12345–12394 中，依次做1 mA op、改5 mA再 op；checker 按每种负载50值算均值及 sample stddev，两个 mean±3σ 区间均须在0.35–0.45 V。 | check 记录1 mA为0.3966–0.4052 V，5 mA为0.3964–0.4050 V；flat 的 minimum_three_sigma_output=0.3966，并非两负载最小下限，应不能用作完整MC判定摘要。 |

`tb_point.spi` 固定连接0.4 V参考、40 µA偏置电流 sink、10 pF外置输出负载和 `loop_out/pass_gate` 串联注入源，再替换corner/supply/temp/load；它不是读一份已知结果。上述每行都需要“规定场景、对应测量、聚合规则和判定门限”才能得到 Value 与 Pass/Fail，JSON本身只是已有运行的结果。扁平MC字段为什么只取1 mA、如何生成尚无公开脚本；这里只能核实结果遗漏了更低的5 mA下限，不能推断生成过程。

实际执行处理也有边界：先跑名义点，只以 `0<VOUT<VIN`、输入电流>0及这两项有限测量作为 functional gate；不是要求名义点全部指标先通过。functional成立才继续其余53点及50个MC过程。缺ngspice等 `OSError` 返回失败/空测量；非零进程退出使该结果不满足 `finite`；NaN/Inf测量不入字典；并行任务抛异常则被略去，导致覆盖不足。代码未将这些情况单列为 environment error，而是完整性或相应check失败。数值越限与缺测量都可能使check失败，但在代码里路径不同。若测量只缺一部分，有些其他check仍可能通过；headroom依赖point_complete、MC依赖mc_complete，complete_signoff依赖两者。最终 [write_results](https://github.com/Arcadia-1/analog-design-bench/blob/972f7cd7c95381134387b250edf18f3bd23bdd25/tasks/sky130-nmos-pass-ldo-0p4v-pvt-mc/tests/utils.py)按7项passed/total写reward与CTRF，[test.sh](https://github.com/Arcadia-1/analog-design-bench/blob/972f7cd7c95381134387b250edf18f3bd23bdd25/tasks/sky130-nmos-pass-ldo-0p4v-pvt-mc/tests/test.sh)在电路缺失/合法性检查失败或没有reward文件时提供零reward。计数消息中的54/54仅说明结果对象数量，不能代替所有必需测量完整性判定。

对 VA 的尚未定案选项：采用 Specification | Metric (threshold) | Value | Pass/Fail 展示时，可拆出每个双边或组合条件，并另列覆盖完整性；也可保留一项spec下的多个metric。但不能把上述已发布flat摘要当作完整验收清单。此处只核实来源，未修改我们的checker、报告格式或任务流程。

后续讨论已在 2026-10-14 确认采用完整验收表、表格与 JSON 同源，以及先审验收方案再实现与校准。

## Modeling choices

This all-VA spec-modeling task asks for continuous ideal tracking, close-time sampling and persistent hold, not a rising-edge sampler or the finite-acquisition sibling. There are no device, leakage, injection, PVT, noise, or load-response requirements. A single ideal voltage source drives the output; different correct VA source structures are accepted. The task does not narrow legal VA syntax to a backend subset. Spectre is the intended backend, with qualification pending. The Dockerfile provides the task-local Python checker; the trusted deployment must supply licensed Spectre. Its base reuses the repository-pinned Python image. No image was built or run in this round.

The public instruction owns all behavior and grading rules. [Public diagnostics](environment/starter/testbench/README.md) provide analytical expectations, draft Spectre bench generation and explicit-tolerance CSV checks for all principal semantics. Agent-written tests are development aids. [Final case construction](tests/final_cases.py) reruns these public cases from future frozen submissions and adds exploratory parameter, timing, input and history combinations. Shared observation/checking code is intentional. Trusted execution and untouched holdout conditions are separate guarantees. Rebuilding an equivalent bench is normal engineering.

The analytical reference is an interval calculation: reset selects vinit, track selects vin(t), and hold selects the most recent eligible closing-time vin after reset release, otherwise vinit. It reads neither candidate nor gold waveforms. Fixed independent anchors and the measurement plan are in the [calibration plan](tests/calibration/README.md). Numerical diagnostic defaults only make the draft examples inspectable and are not finalized acceptance values. Native execution now requests simulator strobes and reads PSF node values; it does not trust candidate-printed results.

### Proposed Spec decisions, not yet adopted

The user's follow-up asked how the range and accuracy were chosen. The original circuit gives no unique grading precision or complete legal-domain contract. Static extraction of its supplied stimulus gives vin 0.2–1.7 V, maximum slope approximately 7 V/ns, fixed 200 ps controls, an 8 ns shortest track window, 5 ns shortest combined control-crossing separation and 17 us stop time. The evidence and arithmetic are retained in the current run's `runtime-contract/source-stimulus-analysis.json`.

The revised recommendation is a declared assessment envelope with vin/vinit 0–1.8 V, vth 0.3–1.5 V, fixed 200 ps 0/1.8 V control edges, vin slope at most 7 V/ns, tracking windows at least 8 ns, same-instance crossing separation/start/stop distance at least 5 ns and duration at most 20 us. Voltage endpoints and time round-ups are author choices around the source scale, not circuit limits proven by that one example. The proposed threshold interval keeps 0.3 V margin to the control rails and allows nondefault sampling thresholds. Equality at startup remains independently tested.

For this first version, the recommendation is to exclude same-instance simultaneous controls, later threshold parking and discontinuous vin at sample time. These need new conventions beyond the accepted source behavior. Inter-instance simultaneity, reset priority, closure during reset and both reset-release modes remain required. None of these exclusions is a backend syntax restriction.

The revised accuracy recommendation is 2 mV absolute output error, matching the sibling finite-acquisition task's declared voltage-error scale. This is an author fidelity choice, not a measured result or a uniquely derived application requirement. At the source slope of 7 V/ns, 1 ps sampling uncertainty alone would produce 7 mV error. An author-side target budget of 0.1 ps for crossing uncertainty would instead consume 0.7 mV. A proposed 0.01 ps native timestamp budget adds at most 0.07 mV at that slope, leaving room for solver and measurement error under 2 mV. These budgets are unverified targets. They do not allow model aperture delay or prescribe a source operator.

Domain, boundary inclusion/exclusion, voltage tolerance and any output observation exclusion belong in the public Spec because they determine acceptance. Maxstep and solver tolerances are implementation settings for that same acceptance rule. The 0.1 ps author budget is not a separate DUT timing specification. The user has asked for this distinction and has not yet adopted the recommendation. The instruction's named TBDs therefore remain visible rather than being silently replaced.

Before actual model trials, reconcile cases to the adopted domain and freeze case generation/settings/checker identities. The current author extensions remain proposals. Actual correct-alternative acceptance, semantic VA mutant rejection, runtime image/installation, isolation, numerical budgets and final-score calibration are all not run.
No human acceptance, score, source behavior alignment, or backend support is inferred from static lint or Python tests. The old package's evidence remains in the backup without being relabeled as evidence for this version.

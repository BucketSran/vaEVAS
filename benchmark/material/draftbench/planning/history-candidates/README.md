# 历史 benchmark 投稿候选规划

最终建议是 **108 项主候选，归属 103 个规划单元，另保留 1 项条件后备**。其中 105 项已获用户确认进入规划池，初次终审建议增加 3 项验证任务。这里的“主候选”表示优先建设方向，尚不是论文正式题集或建成题包；最终录取数量取决于题目审核、参考解、评分校准和模型实测。

2026-10-26 更新：结合用户提供的 Grok 审查，对这 108 项逐项补充可复用内容、特有改造、建设成本、优先级和意见处理理由。数量、动作和来源归属不变，U30 仍为后备。当前安排为 **P0 首批 15 项、P1 第二批 65 项、P2 后置 28 项**。这些数量来自逐项判断，不是预设配额或正式题量。

本规划只覆盖历史 v1–v4，未加入现有 56 题、早期 41 题包、独立 R01 或 UWB 新资产，也未建题、修改历史合同、运行仿真或模型实验。EVAS 的当前支持范围不作为选题排除条件。

规划单元按历史来源锚点计数。跨电路组合保留支持来源，不把所有支持模块再算成新案例。
旧版本、改题、S/R/T 派生形式都不自动成为独立样本。训练/开发/测试划分需按来源及组合依赖一起分组，避免同源泄漏。
登记表的 `primary_ref` 指直接取材的案例或条目，`case_anchor` 指去重后的电路锚点。例如 U25 的直接来源是 LDO 的 TB 条目，仍归 C403；U26 同样归 C278。`historical_forms.assessment` 保留旧筛查判断，当前候选状态以 `candidates.status` 为准。
`priority` 现表示建设顺序，原值保存在 `previous_priority`；它不等于题目难度。`construction` 记录作者工作种类、成本和排序理由，`grok_review` 记录对应历史意见及处理理由。题目预估难度仍未实测。

## 对 Grok 意见的处理

用户所指评论实际位于 [Issue #159](https://github.com/BucketSran/vaEVAS/issues/159#issuecomment-6401348069)。GitHub 发布者为用户账号，Grok 身份沿用用户说明，未据账号推断模型身份。评论按历史来源代表列出 342 项摘录完整、101 项规格缺口和 12 项观测量不符；这些来源数不能与本规划的任务数相加。

按来源对应，当前 108 项中，75 项关联“摘录完整”组，29 项关联“规格缺口”组，4 项关联“观测量不符”组。这只是意见对应，不是本轮对成熟度的认可；U30 另关联“摘录完整”组。评论没有直接审查本规划新增的测量、集成或诊断职责。

处理原则是核对完整原题，再判断独立工程责任、可区分的错误和作者建设成本。采纳有价值的行为或缺口，同时明确不采纳的推断：

- 去抖 C176 的 `stable=12n`、C260 的 100 ns 低通、C264 的 zi 系数、C266 的升降斜率均已在原题其他段落公开。C169/C170 的初始参考与 LSB、C279 的死区、C411 的电源窗也已有定义。不能因旧行为摘录缺了参数段而重造这些参数。
- 首选 v4 的 C348 AGC、C360 IQ 下变频和 C384 校准环已给出完整更新关系。评论使用的较简略摘录或其他形式不代替选定版本的合同；仍需补合法域、边界和独立评分。
- C105 流水 ADC 的粗电平/残差关系、C067 的下垂关系、C300 的累加模数等缺口仍成立，逐项明确补齐。
- 采纳时间失配、毛刺、镜像和四象限插值的观测问题。U03/U06/U12/U23 必须使实际采样时刻、输出波形、I/Q 观测或输出相位发生相应变化；补代理公式不能完成改造。
- “摘录完整”也不保证工程目标成立。例如 U22 的旧仪表读输入占空比，校正输出不会改变被测误差；U15 逐沿锁不同延迟与保持脉宽存在冲突；U24 的最近恢复沿可能尚未发生。这些继续保留候选，但先修正常合同。

同源案例合并计数，任务按独立交付责任判断。旧 TB 只实例化、激励和保存波形时作为配套；真正提交独立检查器的 T 与提交 DUT 的 S 可以分别录取。R 必须先有可复现故障和正常合同，不能把规格矛盾伪装成故障。所有相关形式及组合依赖仍按来源分组划分数据集。

| 校准与伺服 | 4 | 2 | 0 | 0 | 2 | 0 | 4 |
| 电源与复位 | 12 | 10 | 0 | 2 | 1 | 0 | 13 |
| 滤波、积分与包络 | 6 | 5 | 0 | 1 | 0 | 0 | 6 |

语言、工具与分析模式单列为配套，不作为第 13 个电路功能族。基础层仍限于已选的 C066、C083、C128、C250、C396、C402 六项。没有另补大量静态传递、编码或单状态更新题。

这些是覆盖记录，不是题量配额。时钟类占比较高，后续应检查其事件机制是否重复；R 较少，D 为零。D 需要有来源、条件和独立测试划分的观测数据，人工查表或把公式样本改名不能补齐这一缺口。I 必须提供可用子模块并考察集成责任；T 必须有独立可验证的测量/覆盖职责，不能只把 S 改标签。

## 剩余资产为什么暂不增加独立题

“未入主候选”不表示无用。422 案例及 210 个早期排除条目的来源均保留，具体去向可用下面的查询命令查看。

| 复查方向与具体例子 | 最后判断 |
| --- | --- |
| measurementflow、finalstepaveragemetricfile、fileprofilereplaycontroller | 计数、均值、文件位置操作是真实行为，但没有完整的被测对象、实验设计或失效判断。作为 T 任务的配套，不独立计主候选。replay 的名字也不意味着真实时序回放。 |
| rdistexponentialjitter、rdisterlanglatency | 随机数被加到幅值，没有改变边沿时刻或实际延迟。保留随机源素材，不能按名字增加抖动/延迟工程题。 |
| AC/noise 系列、temperatureenvironmentmetric | 当前公开合同主要是分析函数、噪声源或环境查询，再输出控制量。若发展成频谱、统计或温漂验证，还需新对象与独立真值；这不是被遗漏的现成完整题。 |
| kclcapacitorddtcurrent、kclinductoridtvoltage | 单支路算子可作基础与回归素材。后者合同写 V=L·积分(I)，与电感命名不符，应先修正目标模型和量纲。此结论与 EVAS 是否支持 KCL 无关。 |
| C206/C207 与其他 hierarchy 变体 | 给定增益/限幅子模块的接线与参数传播可做基础 I；目前不再扩张基础层。多文件、指定实例名或换端口顺序本身不等于系统集成难度。 |
| C055/056/057 的 TB、C176/C275 的 TB | 捕获、泄漏、去抖和近碰撞场景可复用，但原交付多是固定刺激与 save 清单。先作为对应主例的作者校准场景；只有形成独立验证责任才另立 T。 |
| C298/C317、C326/C327、C349/C357 | 分别保留为 U15 延迟、单稳态、IQ/均衡方向的变体或支持素材。先解决重触发、相位/反馈定义，不能依名称升级。 |
| 40 条合并来源 | 保留原题号、版本及合并目标。位宽、摆幅和接口别名优先作参数变体；既有 LDO/ADPLL TB 已分别成为 U25/U26，不因另一个 DUT/e2e 名字再算新题。 |

本轮没有在这些剩余条目中找到证据足够、又不与现有职责重叠的其他独立主候选。这是当前规格与工程价值下的判断，不是证明它们无法发展成新任务。

## 建设顺序与进入正式集的条件

已有 79 个历史任务形式和升级方向统一排序，不再按来源整批先后建设。每项正式录取前都要有独立参考、正常与违约对照、评分校准和最小 starter 审核；详情页只列各题特有的改造。

| 顺序 | 项数 | 建设安排 |
| --- | ---: | --- |
| P0 首批 | 15 | C055 的 S/R、C056 的 S/R、C060、C105、C109、C176、C260、C264、C266、U15、U16、U17、U18。先完成明确的独立机制与有界规格修订；S/R 分别确认职责，同源共建对象。 |
| P1 第二批 | 65 | 整理其余成熟机制，建设独立测量/集成对象。U04/U07/U25/U27/U28/U29 等与健康 DUT 共建，U26 依赖 C278 的正常对象，U22 依赖占空比仪表和延迟部件。 |
| P2 后置 | 28 | 新对象成本高或近似职责待实测的方向；包括既定六项基础题，它们随核心任务校准，不人为增难。U03/U06/U12/U14/U20/U24 等需较多新对象或真值；U21 先复现故障。 |
| HOLD 后备 | 1 | U30 不计入 108，先确认实际消费者的错误捕获及诊断价值。 |

成本 L/M/H 是作者建设工作估计，分别表示主要整理与有限边界、补行为/事件关系与参考、新增对象/真值或复杂故障复现。108 项中 L17、M63、H28；与求解难度分开，也不代表工期承诺。按主要工作分为基础整理 6、整理既有规格 18、补行为边界 58、新增对象或真值 25、故障核实 1。这些是每项的主要瓶颈，彼此仍可能共享工作。

保留必要公式、单位、采样含义和复位边界，不通过缺失正确行为提高难度。若允许求解者选择控制律，应公开性能约束并按这些约束评分，不能暗中要求复现唯一轨迹。S/R/T/I 的正式分类仍取决于实际交付责任，不能把旧 S 改标签就计作 T 或 I。

建设时先完成一种代表，再判断近似变体是否值得单列。用小规模实测校准难度后，再讨论现有 56 题如何去重加入；本轮没有启动这两项工作。CVDP 对标需要统一任务责任、交互预算和实际表现，当前 M/H 标注没有证明同等难度。

109 个登记项全部是候选资产。复用说明只描述历史内容能继承多少，**可直接加入正式题集的数量本轮没有认证**。正式录取仍走[题目建设与审核](../../../../README.md#从草稿进入正式题集)。

## 来源可用性与检查方式

来源共 1269 份文件身份，其中 676 份原件在仓库内，593 份为 local-only 的 v2/v3 原件或历史修订。这里保存了 751 条公开行为摘录供审核选题理由，但摘录不是完整原题包。未声称这 593 份完整原件已公开或可在新机器直接运行；两条多段摘录标记为 `assembled_historical_extract`。改题时必须取回相应完整接口和参数，不可将旧版 gold 套给修订合同。

原始资料的使用与分发仍遵循[历史资料说明](../../../historyref/README.md)。本 PR 只保留审核所需登记和摘录，不复制仿真器、完整旧源码树或波形。

在仓库根目录执行：

```bash
python3 -B benchmark/material/draftbench/planning/history-candidates/verify.py
python3 -B benchmark/material/draftbench/planning/history-candidates/verify.py --show U29-T1
python3 -B benchmark/material/draftbench/planning/history-candidates/verify.py --show C206
python3 -B benchmark/material/draftbench/planning/history-candidates/verify.py --show measurementflow
```

校验检查计数、来源归并、候选身份、行为摘录哈希、仓库内原件哈希和文档链接。local-only 原件在导出时已逐份核对身份，新机器仅能验证随表保留的摘录与声明；不能把这种差异算作完整原件复验。

初次终审回读了 92 条语言/工具类公开行为、40 条合并映射、39 个未入池历史 T 和 2 个 I 的既有评估，以及重点合同和 5 份实现；此前的 57 份 TB、52 个 R 审查按来源沿用。

2026-10-26 意见处理核对了全部 109 个登记项的首选公开合同身份，逐项回查任务、参数和行为段，并对争议接口和版本回读全文。评论原文及本地完整读取材料保存在任务运行区，仓库保留相关意见与补充公开上下文。未逐份深审所有版本的 gold/checker，未运行仿真，也未新增独立第二审阅；这是作者对外部意见的处理，PR 继续供用户或其他审阅者审核。

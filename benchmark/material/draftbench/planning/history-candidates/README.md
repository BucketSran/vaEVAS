# 历史 benchmark 投稿候选规划

全面核对 Grok 的342项摘录完整来源及113项待改造来源后，建议将原108项扩展为 **138项规划候选，归属133个规划单元，另保留U30一项条件后备**。新增30项均有逐项理由，尚待用户审核；原105项确认与3项终审建议的状态保持。候选池没有题量上限，正式录取仍取决于合同、独立参考、评分校准和实测难度。

本规划只使用历史v1–v4资产，未加入现有56题、早期41题包、独立R01或UWB新资产。本轮只做规划，没有建题或修改历史合同，没有运行仿真和模型实验。EVAS当前支持范围不作为选题排除条件。

优先级是建设顺序，不是正式主集/扩展集录取。建设成本L/M/H分别表示主要整理、补行为关系与参考、新增对象/真值或复杂故障复现；当前L17、M88、H33，是作者工作估计而非工期承诺。每项都有独立理由，未按功能矩阵分配题量。

正式录取前仍需完整公开合同、独立参考、正常与违约对照、评分校准和最小starter审核。公开必要公式、单位、采样含义、复位和输出边界；允许自主控制律时按公开性能目标评分。完整状态更新或测量实现不作为默认填空骨架，也不靠缺失正确行为制造难度。

原题版本、S/R/T派生形式与实质复用的DUT/故障/真值要共同考虑划分，避免同源泄漏。普通公共工具不自动把所有任务合成一个数据组。129条变体保留差异和来源，后续由任务责任与实测决定是否值得独立录取。

### 四项系统与修复方向的具体责任

**C109-S1。** [原合同](../../../historyref/v4/release/benchmarkv4-r53/tasks/342-sar-adc-system-4b/public/instruction.md)要求下一时钟沿采样、随后四沿逐位判决、保持样本并发布done。应给完整模块职责、接口和时序，不给实现好的转换链。独立预期从采样时刻的输入与公开试位规则推导；转换中改变vin，检查sample_dbg不跟随，并核每拍dac_dbg、码及done。只有终码正确而中间过程错误的实现不能通过；外部行为满足完整公开合同的等价实现不因内部写法不同被拒绝。

原合同的DAC式为`vref * code / 16`，[gold](../../../historyref/v4/release/benchmarkv4-r53/tasks/342-sar-adc-system-4b/evaluator/solution/binary_weighted_cdac.va)却加了`vss`；非零vss时不是同一行为。[控制器](../../../historyref/v4/release/benchmarkv4-r53/tasks/342-sar-adc-system-4b/evaluator/solution/sar_controller.va)在忙时start也重新武装，合同未明确。建议保留完整转换责任，公开忙时重新武装规则，并明确vref是跨度还是绝对端点、采样与复位优先级。固定vss=0或排除同刻事件只是可选范围收缩，尚非用户决定，也不能代替解决合同冲突。常规作者工作包括逐拍观察窗口、样本保持、比较门限和参考误差的核对。历史公开激励在转换中保持vin不变，不能单凭它证明采样时刻正确。

**C290-S1。** [原合同](../../../historyref/v4/release/benchmarkv4-r53/tasks/361-dll-delay-line-lock/public/instruction.md)已有输入沿来源、每沿独立锁码、一次完整比较更新一次、0至31饱和、连续四次资格和复位取消。给定这些职责，由求解者实现整条DLL。评分应从输入与输出阈值交点独立对应边沿，核实际延迟、比较方向、步进、资格和取消，不能只看lock或码是否变化。早晚沿、码饱和、待发时变码、禁用后恢复都可形成独立错误对照。

[phase_detector](../../../historyref/v4/release/benchmarkv4-r53/tasks/361-dll-delay-line-lock/evaluator/solution/phase_detector.va)把`0.25 * unit_delay`内的误差视为无纠正，原合同只允许同刻不纠正；其方向、误差与完成信号一起平滑，再由[lock_detector](../../../historyref/v4/release/benchmarkv4-r53/tasks/361-dll-delay-line-lock/evaluator/solution/lock_detector.va)在完成信号过阈时读取，未证明读取的是稳定的新结果。[delay_line](../../../historyref/v4/release/benchmarkv4-r53/tasks/361-dll-delay-line-lock/evaluator/solution/delay_line.va)的定时事件与实际输出交点也不能直接等同。先定义可观察沿时刻与数值观察预算，消除死区冲突，再建立参考。建议首版同频、只含单周期内可达相移，不新增频漂或跨周期捕获；这是待确定的建模范围。上下沿允许使用不同码，不能照搬U15的保持脉宽要求。合法边沿间距要由延迟范围和脉冲可表示性推导，不能为迁就旧实现任意排除输入。

**U22-I1。** [359原合同](../../../historyref/v4/release/benchmarkv4-r53/tasks/359-duty-cycle-corrector/public/instruction.md)与[gold顶层](../../../historyref/v4/release/benchmarkv4-r53/tasks/359-duty-cycle-corrector/evaluator/solution/dcc_top.va)都测clk_in；trim虽改变clk_out下降沿，却不能改变被测误差。改成测clk_out是必要改造，但仅换线不足以构成所需集成责任。建议提供健康仪表、执行器与明确的接口稳定期，求解者完成控制更新、结果向后续完整脉冲交接、资格及取消恢复。控制律是固定逐步调码还是允许自主选择，仍需确定；无论哪种都不能交付完整控制器后再把换线包装成困难任务。

[执行器](../../../historyref/v4/release/benchmarkv4-r53/tasks/359-duty-cycle-corrector/evaluator/solution/delay_pair.va)在上升沿锁存0至15的trim，只延迟下降沿。忽略过渡、没有重叠时，推导有`Dout = Din + k * trim_step / T`。旧公开周期2.5ns和默认5ps步长最多增加0.03占空比；这不是校准结果。目标窗必须含可达码，延迟不能跨越原低电平区间，不能承诺修正所有高于目标的输入。还需确定测量完成后哪一脉冲采用新码；旧[仪表](../../../historyref/v4/release/benchmarkv4-r53/tasks/359-duty-cycle-corrector/evaluator/solution/duty_meter.va)与[控制器](../../../historyref/v4/release/benchmarkv4-r53/tasks/359-duty-cycle-corrector/evaluator/solution/trim_controller.va)同时平滑发布和读取，尚未校准交接。独立测实际clk_out占空比与持续误差，检出仍测输入、在途脉冲被重定时、饱和假锁与取消遗漏。C331/U15是可复用功能来源，不自动等同已验证可直连的部件。

**U21-R1。** [088源码](../../../historyref/v4/release/benchmarkv4-r53/tasks/088-cppll-tracking-reacquire-timer/evaluator/solution/cppll_timer_ref.va)使用真实反馈边沿，控制电压实际驱动DCO；每N个DCO上升沿翻转反馈，完整周期分频比是2N。`t_ref - t_fb`误差配正PI和正kvco存在局部反馈方向问题。[1088坏版](../../../historyref/v4/release/benchmarkv4-r53/tasks/1088-cppll-tracking-reacquire-timer-bugfix/public/buggy_bundle/cppll_timer_ref.va)另把lock恒置高并去掉控制电压平滑；其fixed的两个VA文件与088 gold逐字节相同，没有修复方向。二者是同源不同故障素材，不能把1088 fixed当正常参考。

本地历史D4报告称改负反馈后原增益仍滑移、加大增益后持续重锁。本轮读到报告、变体及gain deck，没有重算波形或重跑，不据此赋予当前参考资格。建议固定参考源及作者证明可恢复的工况，公开2N、捕获域、初相、阶跃范围、持续窗口和恢复期限，再要求求解者诊断修复。允许调增益或重设计控制律会改变修复责任，不能暗中评分。独立核实际频比、相位漂移、周期滑移、分频和lock资格；历史checker的半周期重锁高电平及约±3%频率关系不足以证明持续跟踪。健康参考未建立前，正反馈、弱增益、分频误读和恒高lock只能列作拟用错误对照，不能声称已校准。
